### 依赖版本

`gradle/libs.versions.toml` 里的版本号是搭建时的基线。**首次同步后请执行一次依赖更新检查**，特别注意：

- ~~`material3` 需要 1.4.0 及以上才有 Expressive API~~ —— **已确认可用并已启用**。
  当前锁定的 `1.4.0-alpha13` 就带 `MotionScheme`，`Theme.kt` 里的
  `motionScheme = MotionScheme.expressive()` 已经生效。
  注意它需要**单独的 opt-in 标记** `ExperimentalMaterial3ExpressiveApi`
  （和 `ExperimentalMaterial3Api` 是两个开关，只开后者会报「experimental API」编译错误），
  已统一加在 `build-logic` 的 `configureKotlinAndroid` 里。
  剩下的事情是把 `MotionTokens` 收敛为只保留项目特有的补充令牌。
- ~~中文字体占位~~ —— **P0 已落地**：`Type.kt` 已内嵌 **Noto Serif SC
  （标题/数字，400/500）+ MiSans（正文/UI，400/500/600/700）**，
  字体文件在 `core/designsystem/src/main/res/font/`，已按 GB2312 + 常用标点
  子集化（工具：`tools/subset_fonts.py`，来源与授权见 `docs/FONTS.md`）。
  `TypographyTest` 的 sp/em 与 15 样式约束不受影响，改 `Type.kt` 后仍要跑一次。

### realme GT Neo5 SE 上的调试

- 开发者选项里打开 **USB 调试**，以及 **「禁止权限监控」**（否则 adb 安装的包会被反复拦截权限）
- ColorOS 对 debug 包有额外安装拦截。**建议自己签一个固定 keystore 出 release 包日常使用**：
  R8 优化后才是真实性能，且系统不会区别对待
- 首次安装后按「保活自检」逐项设置（自启动、后台活动、电池不限制），
  否则提醒、自动记账、小组件刷新都会被 ColorOS 杀掉

## 二、项目结构

```
:app                    组装层。唯一知道「所有 feature 都存在」的地方
                        └ 导航图注册、Application、Manifest、图标资源

:core:common            时间工具、Result 封装、Dispatcher 注入、跨模块协作契约
:core:designsystem      色彩、字体、形状、MotionTokens、通用组件（卡片/空态/骨架屏）
:core:database          Room 数据库、实体、DAO、迁移
:core:datastore         偏好设置、功能开关
:core:network           OkHttp 基建
:core:ui                导航契约 Route、首页卡片插槽 HomeCard

:feature:home           首页。只做卡片编排，不认识任何具体业务
:feature:todo           待办。**新增 feature 的参考实现，照抄这个模块的结构**
:feature:anniversary    纪念日。含农历倒数
:feature:period         经期。含预测与月历
```

`:core:common` 里两个值得知道的东西：

- `AppTime` / `AppFormatters` —— 时间换算与格式化的唯一入口，不要在别处自己写 `DateTimeFormatter`
- `LunarCalendar` —— 离线农历换算（1900~2100）。有全量往返测试兜底，
  **改动那张 `LUNAR_INFO` 表之前先跑 `:core:common:testDebugUnitTest`**

### 依赖规则（不可违反）

1. `:feature:*` **之间永远不互相依赖**
2. `:feature:*` 只能依赖 `:core:*`
3. 需要跨 feature 协作时 → 在 `:core:common/contract` 定义接口，提供方实现并 Hilt 绑定，
   调用方只注入接口

> 例：资讯页的「存为笔记」不 import `:feature:note`，而是注入 `NoteWriter`。
> 这样删掉 `:feature:note` 时，只需换一个空实现，资讯页一行都不用改。

## 三、如何新增一个 feature

以「喝水打卡」为例，完整步骤：

**1. 建目录与构建脚本** — `feature/water/build.gradle.kts`

```kotlin
plugins {
    alias(libs.plugins.myapp.android.feature)
}

android {
    namespace = "com.myapp.feature.water"
}
```

就这么多。约定插件 `myapp.android.feature` 已经把 library + Compose + Hilt + 全部 core 依赖配好了。

**2. 注册模块** — `settings.gradle.kts` 加一行

```kotlin
include(":feature:water")
```

**3. 加数据层** — 在 `:core:database` 的 `model/` 和 `dao/` 下加对应文件，
在 `MyAppDatabase` 的 entities 里加一项，**版本号 +1 并在 `Migrations.kt` 里补一条 Migration**
（同时加进 `ALL_MIGRATIONS` 数组，否则等于没写）。

> 手写迁移 SQL 最快的验证方式：先改完实体编译一次，
> Room 会把新版本的建表语句导出到 `core/database/schemas/<版本>.json` 的 `createSql` 字段，
> 拿它和你写的 `execSQL` 逐字符比对。反引号、`NOT NULL` 的位置、索引名都必须一致，
> 差一个字符 Room 就会在启动时的 schema 校验里崩掉。

**4. 加首页卡片**（可选）— 实现 `HomeCard` 并绑定：

```kotlin
class WaterHomeCard @Inject constructor() : HomeCard {
    override val id = "water"
    override val defaultOrder = 350

    @Composable
    override fun Content(onNavigate: (Route) -> Unit) { /* ... */ }
}

@Module
@InstallIn(SingletonComponent::class)
interface WaterHomeCardModule {
    @Binds @IntoSet
    fun bind(card: WaterHomeCard): HomeCard
}
```

**首页代码一行都不用改**——`HomeViewModel` 注入的是 `Set<HomeCard>`，会自动发现它。

**5. 加页面路由**（可选）— 在 `:core:ui` 的 `Route` 里加一个 `@Serializable data object Water`，
在自己模块里写 `NavGraphBuilder.waterGraph()`。

**6. 接入 `:app`** — `app/build.gradle.kts` 加 `implementation(projects.feature.water)`，
`AppNavHost` 里加一行 `waterGraph(onNavigate, onBack)`。

### 扩展性验收标准

- 上述流程中，**改动的已有文件只有 3 个**：`settings.gradle.kts`、`app/build.gradle.kts`、`AppNavHost.kt`
  （不含首页——首页完全不用动，这是插件机制的价值）
- 删除任一 `:feature:*` 模块后，项目仍应能编译通过

## 四、几条必须守住的纪律

**数据库迁移**
本项目数据**没有云端备份，丢一次就永久没了**。因此：
- 严禁 `fallbackToDestructiveMigration()`
- 每次改表必须写 `Migration` 并提交 `schemas/` 下的 JSON（已配置自动导出，且不在 gitignore 里）
- 迁移要有测试

**提醒调度**
定时提醒**一律用 `AlarmManager.setExactAndAllowWhileIdle`**，不要用 WorkManager。
ColorOS 会冻结后台，WorkManager 的周期任务在这台机器上不可靠。
WorkManager 只用于可延迟的任务：RSS 拉取、知识池刷新、数据清理。

**动效**
- 所有动画参数走 `MotionTokens`，不要各处硬编码 `tween(300)`
- 144Hz 屏帧预算只有 **6.9ms**：只用 `graphicsLayer` 类属性动画（translation/scale/alpha），
  严禁在动画中触发 layout/measure
- 尊重 `LocalMotionLevel`，Reduced/None 档要真的降级

**视觉**
- 不用纯白 `#FFFFFF` 作背景，不用纯黑 `#000000` 作深色底
- 层级用 **1px 描边**表达，不用阴影
- 一屏最多一个 Accent 焦点

**排版：`letterSpacing` 绝不能用 `.em`**

`Type.kt` 里所有 `letterSpacing` / `fontSize` 一律 `.sp`，且 15 个样式必须全部显式定义。

原因是一次真机崩溃：`bodyLarge` 写了 `0.01.em`，而 `bodySmall` 没定义、走 Material 默认的 `0.4.sp`。
`OutlinedTextField` 的 label 在聚焦时会对这两个样式做 `TextStyle.lerp`，
而 lerp **无法在 Em 与 Sp 之间换算**，直接抛：

```
java.lang.IllegalArgumentException: Cannot perform operation for Em and Sp
    at androidx.compose.ui.text.TextStyleKt.lerp
    at androidx.compose.material3.internal.TextFieldImplKt$CommonDecorationBox...
```

后果是**每一个带 label 的输入框一进页面就崩**，而且编译期发现不了、Preview 里也未必触发。
`TypographyTest` 已经把这条规则钉死，改 `Type.kt` 后跑一次 `:core:designsystem:testDebugUnitTest`。
