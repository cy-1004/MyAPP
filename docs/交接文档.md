## 一、这是什么项目

一个**单人自用的 Android 原生 App**，把日常记录（纪念日 / 经期 / 待办 / 记账）、
个人知识库、行业资讯聚合在一个入口里。

**四条硬约束，任何时候都不能违反：**

| 约束 | 含义 |
|---|---|
| **仅安卓原生** | 不用 Flutter / RN / KMP |
| **无自建服务器** | 所有数据本地，只直连公开网页与 RSS |
| **单人自用，不上架** | 所以 `USE_EXACT_ALARM` 这类 Play 严管权限可以用 |
| **拓展性是一等需求** | 加一个 feature 不该改动已有模块，见第四节 |

另外两条同样重要：

- **数据无云端备份，丢一次就永久没了** → 严禁 `fallbackToDestructiveMigration()`，
  每次改表必须写 Migration 并提交 `schemas/` 下的 JSON。
- **UI 走 Claude 风格**：暖色、简洁、克制。不用纯白/纯黑，层级用 1px 描边不用阴影，
  一屏最多一个 Accent 焦点。

目标设备：**realme GT Neo5 SE**（realme UI 7.0 / Android 16 / 144Hz），
minSdk 35 · targetSdk 36 · compileSdk 36。

### 真机调试

设备通过 USB 连着，`adb` 在 `%LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe`。

```bash
export MSYS_NO_PATHCONV=1
ADB="/c/Users/cy-10/AppData/Local/Android/Sdk/platform-tools/adb.exe"

"$ADB" install -r app/build/outputs/apk/debug/app-debug.apk   # -r 保留数据
"$ADB" shell am start -n com.myapp.debug/com.myapp.MainActivity
"$ADB" logcat -d -s AndroidRuntime:E          # 查崩溃
```

**在 Git Bash 里跑 adb 要加 `export MSYS_NO_PATHCONV=1`**，
否则 `/sdcard/xxx` 会被转成 Windows 路径。

> ⚠️ **绝对不要用 `adb uninstall` 或 `adb shell pm clear` 验证首启逻辑**
> --这会清掉用户全部数据（纪念日、待办、经期记录），且 `allowBackup="false"`
> 没有云端备份，丢了就是永久丢了。要验证首启向导，在一台没有用户数据的
> 测试机或模拟器上做，或者接受「老用户升级跳过」这条路径就够覆盖了。

无 UI 自动化框架时，可以用 `uiautomator dump` + `input tap` 做确定性的点击验证：

```bash
export MSYS_NO_PATHCONV=1
"$ADB" shell uiautomator dump /sdcard/ui.xml
"$ADB" exec-out cat /sdcard/ui.xml > ui.xml   # 从里面读 text 和 bounds，算出坐标再 tap
```

## 四、架构：加一个 feature 要动哪些文件

```
:app                    组装层。唯一知道「所有 feature 都存在」的地方
:core:common            时间工具、农历、Result、Dispatcher、跨模块契约、提醒、保活检测
:core:designsystem      色彩、字体、形状、动效令牌、通用组件
:core:database          Room 实例、全部实体与 DAO、迁移
:core:datastore         偏好设置（含 onboarding 标志）
:core:network           OkHttp 基建
:core:ui                导航契约 Route、首页卡片插槽 HomeCard
:feature:home           首页。只做卡片编排，不认识任何具体业务
:feature:todo           待办。**新增 feature 的参考实现，照抄它**
:feature:anniversary    纪念日
:feature:period         经期
:feature:note           笔记（M3）。FTS 全文搜索 + Photo Picker 插图
:feature:question       疑问收集箱（M4）。三态状态机 + 转为笔记
:feature:settings       设置页 + 保活自检向导
```

### 依赖规则（不可违反）

1. `:feature:*` **之间永远不互相依赖**
2. `:feature:*` 只依赖 `:core:*`
3. 跨 feature 协作 → 在 `core/common/contract/CrossFeatureContracts.kt` 定义接口，
   提供方实现 + Hilt 绑定，调用方只注入接口

### 新增一个 feature 的完整步骤

**只需改 3 个已有文件**：`settings.gradle.kts`、`app/build.gradle.kts`、`AppNavHost.kt`。

1. `feature/xxx/build.gradle.kts`——只有 6 行：
   ```kotlin
   plugins { alias(libs.plugins.myapp.android.feature) }
   android { namespace = "com.myapp.feature.xxx" }
   ```
   约定插件已把 library + Compose + Hilt + 序列化 + 全部 core 依赖配好。
2. `settings.gradle.kts` 加 `include(":feature:xxx")`
3. 数据层：在 `:core:database` 的 `model/` `dao/` 加文件，
   `MyAppDatabase` 里加实体、**版本号 +1**、`Migrations.kt` 里补迁移并加进 `ALL_MIGRATIONS`
4. 首页卡片（可选）：实现 `HomeCard` + `@Binds @IntoSet` 绑定。**首页代码一行都不用改**
5. 路由：`:core:ui` 的 `Route` 里加类型，自己模块里写 `NavGraphBuilder.xxxGraph()`
6. `app/build.gradle.kts` 加依赖，`AppNavHost` 加一行注册

> 实体集中放 `:core:database` 而不是各 feature，是刻意的（与 PRD 4.7.1 有偏差）：
> Room 的 `@Database` 需要编译期拿到完整实体列表，
> 坚持分散会让 `:core:database` 反向依赖所有 feature，依赖方向就乱了。

### 写迁移 SQL 的正确姿势

手写的 `execSQL` 必须和 Room 生成的建表语句**逐字符一致**（反引号、`NOT NULL` 位置、索引名），
差一个字符 Room 启动时的 schema 校验就崩。

验证方法：改完实体先编译一次，Room 会把新版本导出到
`core/database/schemas/<版本>.json` 的 `createSql` 字段，拿它比对。

## 五、已经踩过的坑（别再踩一遍）

### 1. `letterSpacing` 绝不能用 `.em` ★ 这个坑崩掉过整个 App

`Type.kt` 里所有 `letterSpacing` / `fontSize` **一律用 `.sp`**，且 15 个排版样式必须全部显式定义。

原因：`OutlinedTextField` 的 label 聚焦时会在 `bodyLarge` 与 `bodySmall` 之间做 `TextStyle.lerp`，
而 lerp **无法在 Em 与 Sp 之间换算**，直接抛：

```
IllegalArgumentException: Cannot perform operation for Em and Sp
    at androidx.compose.ui.text.TextStyleKt.lerp
    at androidx.compose.material3.internal.TextFieldImplKt$CommonDecorationBox
```

后果是**每一个带 label 的输入框一进页面就崩**。编译期查不出，Preview 里也未必触发（要聚焦才插值）。
`TypographyTest` 已经把规则钉死，改 `Type.kt` 后务必跑 `:core:designsystem:testDebugUnitTest`。

### 2. Material 3 Expressive 需要**两个** opt-in 开关

`MotionScheme` 在 `material3 1.4.0-alpha13` 里已经有了，但需要
`ExperimentalMaterial3ExpressiveApi`，它和 `ExperimentalMaterial3Api` 是**两个独立开关**，
只开后者会报「This material3 API is experimental」编译错误。
已统一加在 `build-logic` 的 `configureKotlinAndroid` 里。

（顺带纠正一个常见误解：`1.4.0-alpha13` 在语义化版本里排在 `1.4.0` **之前**，alpha 是预发布。）

### 3. Kotlin 不对跨模块的 public 属性做智能转换

```kotlin
// ❌ 编译不过：dueAt 是 :core:database 里的 public 属性，
//    Kotlin 无法保证对方不是自定义 getter
isOverdue = dueAt != null && dueAt < now

// ✅ 先取到局部变量
val due = dueAt
isOverdue = due != null && due < now
```

### 4. `rememberSwipeToDismissBoxState` 的回调只捕获一次

`confirmValueChange` 在创建 state 时捕获闭包，直接传回调会永远拿到第一帧的旧引用。
必须用 `rememberUpdatedState` 包一层。参考 `TodoListScreen.kt` 的 `SwipeableTodoRow`。

另外 `confirmValueChange` **一律返回 `false`**：让数据流去驱动列表变化，卡片滑回原位。
返回 `true` 会让条目停在「已划走」状态，撤销恢复后位置就错了。

### 5. `withContext` 里混用 `return@withContext` 和非 Unit 尾表达式

早退返回 Unit、结尾却是个 `Long`，类型推断会失败。
解决：把函数显式声明成 `: Unit`，尾部逻辑抽成独立的 helper。

### 6. Compose 里的手势累计量不能声明在 composable 作用域

```kotlin
// ❌ 重组会重建局部变量，手势中途就丢了
var dragged = 0f
Modifier.pointerInput(key) { detectHorizontalDragGestures(...) }

// ✅ 声明在 pointerInput 的 lambda 里面
Modifier.pointerInput(key) {
    var dragged = 0f
    detectHorizontalDragGestures(...)
}
```

### 7. `Modifier.padding()` 不接受负数 Dp（运行时崩溃，不是编译错误）

### 8. DatePicker 用的是 **UTC 零点毫秒**

不做转换的话东八区选出来的日期会整体偏一天。参考 `TodoEditScreen.kt` 里的处理。

### 9. Room 2.7+ 不允许 `@TypeConverters` 与 `addTypeConverter()` 双重注册 ★ M3 上线即崩

`Converters` 类只要无依赖，`@TypeConverters(Converters::class)` 注解在 `MyAppDatabase` 上时 Room 会自动用 no-arg 构造实例化它。M3 阶段曾同时存在两套注册（注解 + `DatabaseModule` 里的 `.addTypeConverter(Converters())`），Room 2.7+ 在运行时直接抛：

```
IllegalArgumentException: Unexpected type converter com.myapp.core.database.Converters@...
Annotate TypeConverter class with @ProvidedTypeConverter annotation or remove this converter from the builder.
```

M3 上线时只跑了 `:core:database:assembleDebug` 编译通过就发了，没在真机上 `am start` 过，这条崩溃路径一直没被触发。M4 实施时第一次启动直接红屏，回溯排查才挖出来。

**最终修法**：只保留 `@TypeConverters(Converters::class)` 注解，删掉 `addTypeConverter(Converters())` 调用。`@ProvidedTypeConverter` 是给有依赖、需要 Hilt 注入的 Converter 用的，本项目 `Converters` 无依赖不需要。

教训：编译过 ≠ 跑得起来，Room 的 TypeConverter 校验是运行时检查；任何数据库改动必须真机 `am start` 一次，不能只看 `assembleDebug` 绿了就发。

### 10. Haze 1.5.0 + `Scaffold.bottomBar` 不兼容 ★ 底栏毛玻璃直接失效

`Scaffold` 的 `bottomBar` slot 把底栏和 content 摆成兄弟节点，两者 bounds 不交叠。
Haze 的工作原理是 `hazeSource` 贴在内容上采样像素、`hazeEffect` 贴在底栏上读采样结果--
**两者必须在同一父容器里、bounds 交叠**，兄弟节点采样不到。

**必须放弃 `Scaffold.bottomBar` slot，改用 `Box` 叠层**：`AppNavHost`（带 `hazeSource`）
在底层占满，`MyAppBottomBar`（带 `hazeEffect`）叠在上方 `Alignment.BottomCenter`。
这样底栏的 bounds 完全覆盖在内容之上，Haze 能正确采样。FAB 同理叠在最上层。
参考 `app/src/main/kotlin/com/myapp/ui/MyApp.kt`。

### 11. Haze 1.5.0 的 `HazeStyle` 必须传 `backgroundColor` ★ 运行时崩溃

`HazeStyle` 的 `backgroundColor` 参数在 1.5.0 里是必填的，不传会在运行时（第一次 draw 时）抛：

```
IllegalStateException: backgroundColor not specified. Please provide a color.
    at HazeEffectNode.drawEffectWithGraphicsLayer
```

编译期查不出。`HazeStyle` 还有**两个构造函数重载**，签名很像：
- `(backgroundColor, tints: List<HazeTint>, ...)`
- `(backgroundColor, tint: HazeTint?, ...)`

只传 `backgroundColor + blurRadius` 时会触发**重载歧义**，Kotlin 解析不出该用哪个。
显式传 `tints = emptyList()` 选 List 版本，或传 `tint = HazeTint(...)` 选单值版本。
本项目 `MyAppBottomBar` 用 `tint = HazeTint(surfaceColor.copy(alpha=0.6f))`，
`MultiActionFab` 的遮罩用 `tints = emptyList()`（纯遮罩不需要 tint）。

### 12. `toRoute<Route>()` 不支持 sealed interface Route ★ 导航匹配崩溃

`Route` 是 `@Serializable sealed interface`，子类是 `@Serializable data object`/`data class`。
`NavController.currentBackStackEntryAsState()` 拿到 entry 后，`entry.toRoute<Route>()`
内部用 kotlinx.serialization 多态解码，会抛：

```
SerializationException: Polymorphic value has not been read for class null
```

**必须改用字符串匹配**：

```kotlin
val currentRouteStr = currentEntry?.destination?.route
val topLevelDest = currentRouteStr?.let { str ->
    TopLevelDestination.entries.firstOrNull { dest -> str == dest.route::class.qualifiedName }
}
```

`destination.route` 是类型安全导航生成的全限定类名（如 `com.myapp.core.ui.navigation.Route$Home`），
和 `dest.route::class.qualifiedName` 比较即可。过渡瞬间 `currentRouteStr` 可能为 null，
判空兜底（默认隐藏底栏与 FAB）。

  去注册/取消闹钟，直接注入会在 Dagger 图里形成循环依赖，`Provider` 把取值推迟到
  `rescheduleAll()` 真正调用的那一刻，循环就断开了（第一次接的时候踩过这个坑）。
- `core/common/reminder/ReminderAlarmReceiver.kt`：闹钟触发落地点，渲染通知。
  声明在 `core/common/src/main/AndroidManifest.xml` 里（**不在 :app**——提醒能力是 core 层的东西，
  :app 只负责组装，不该反过来知道这个 receiver 的存在，manifest 会自动合并进最终 APK）。
- `core/common/reminder/ReminderModule.kt`：`@Binds ReminderScheduler`。
- 通知小图标 `core/common/res/drawable/ic_reminder.xml`：占位单色剪影，后续可以换正式设计。
- `app/system/BootCompletedReceiver.kt`：`goAsync()` + `ApplicationScope` 协程调 `rescheduleAll()`。
- `app/MainActivity.kt`：首启请求 `POST_NOTIFICATIONS`（API 33+），拒绝也不阻塞——
  提醒闹钟照样注册，只是不弹通知。

### 三个 `ReminderSource` 实现

| Feature | 提醒键 | 触发时机 |
|---|---|---|
| `:feature:todo` | `todo:$id` | `TodoRepository` 实现；`TodoEditViewModel.save()` 里按 `dueAt` 注册/取消；重复任务生成下一条时（`spawnNextOccurrence`）一并注册 |
| `:feature:anniversary` | `anniversary:$id` | `AnniversaryRepository` 实现；`save()`/`delete()` 里注册/取消，触发时间 = `nextDate - remindDaysBefore` 天，当天上午 9 点 |

`AnniversaryDao` 新增了 `getAllActive()` 一个查询方法（供 `pendingReminders()` 用），
**不是 schema 变更**，没有加字段/加表，不需要新迁移。

## 八、保活自检向导（PRD 9.3）

ColorOS 后台管理是国产 ROM 里最激进的之一，会直接冻结未加白名单的应用，
导致提醒闹钟不响、通知监听失效、小组件不刷新。光有 AlarmManager 不够，
还需要引导用户关闭 OEM 层的后台限制。

### 实现在哪

- `core/common/keepalive/KeepAliveStatusChecker.kt`：检测电池白名单、通知权限、
  精确闹钟、首装判定（`firstInstallTime == lastUpdateTime`）。
- `feature/settings/keepalive/`：向导 UI（Screen + ViewModel + Item 模型）。
- `core/datastore/AppPreferences.kt`：`keepAliveChecked`（完成标志）+
  `keepAliveManualDone`（手动项勾选状态，`stringSetPreferencesKey` 持久化）。
- `app/MainActivity.kt`：splash 挂住读 onboarding 标志，决定 `initialRoute`。
  老用户升级（`!checked && !isFirstInstall()`）直接写 `true` 跳过向导。

### 检测项分四类

| 类别 | 项 | 处理 |
|---|---|---|
| AUTO（自动检测） | 电池优化白名单、通知权限 | API 检测 + 跳转系统设置 / 向导内请求权限 |
| READONLY（只读） | 精确闹钟 | `USE_EXACT_ALARM` 安装即授予，恒通过，只展示 |
| TEXTONLY（纯文字） | 通知使用权 | M5 记账上线后才需要，当前只文字说明 |
| MANUAL（手动引导） | 自启动、后台活动、锁任务 | 无 API，路径文字 + 「我已设置」勾选框 + 「尝试直达」私有 Intent |

手动项勾选状态持久化到 DataStore--这些代表用户在系统设置里做的物理操作，
不会因为离开 App 就消失，复查时应保持已勾选。

### 首启时序（MainActivity）

1. `installSplashScreen()` 在 `super.onCreate()` **之前**
2. `super.onCreate()`（Hilt 在此填充 `@Inject lateinit`）
3. `appScope.launch` 读 `keepAliveChecked`；若 `!checked && !isFirstInstall()`
   写 `true`（老用户升级免打扰）
4. `splash.setKeepOnScreenCondition { keepAliveChecked == null }`
5. 非首启时请求 `POST_NOTIFICATIONS`；首启由向导内请求，避免同时弹两个框
6. `setContent` 的 `initialRoute` 由 `keepAliveChecked` 决定

### 首启返回拦截

首启时 `KeepAliveCheckScreen` 用 `BackHandler` 拦截系统返回键、隐藏 TopAppBar
返回箭头，防止用户跳过自检。`firstRun` 标志由 `AppNavHost` 根据
`startDestination == KeepAliveCheck` 传入。

### 完成导航

`onKeepAliveComplete` 做 `navigate(Home) + popUpTo(KeepAliveCheck){inclusive=true}`。
首启时栈为 `[KeepAliveCheck]`，popUpTo 后清空再 navigate；复查时栈为
`[Home, Settings, KeepAliveCheck]`，popUpTo 只清 KeepAliveCheck，
`launchSingleTop` 复用栈里已有的 Home。

### 项目内 dev 签名

`keystore/debug.keystore` 提交到仓库，`app/build.gradle.kts` 里 debug 和 release
统一用它签名。换电脑不再因 `~/.android/debug.keystore` 漂移导致无法覆盖安装。
`.gitignore` 里 `*.keystore` 忽略所有 keystore，但 `!debug.keystore` 放行这一个。

## 九、各模块的关键设计决定（改代码前先看这里）

### `:core:common` — 农历

`LunarCalendar.kt`：自己实现的 1900~2100 查表换算，离线、零依赖。

**改那张 `LUNAR_INFO` 表之前先跑 `:core:common:testDebugUnitTest`。**
测试覆盖 40 个已知春节日期、13 个已知闰月，以及**全范围逐日往返校验**
（公历→农历→公历 必须严格相等，7 万余天）。

农历算错了 UI 照样显示一个像模像样的日期，肉眼根本看不出来，只能靠测试守。

两个必须容错的边界（不处理的话农历生日每隔几年就「消失」一次）：
- 当年没有对应闰月 → 退回同月份的平月
- 生日是三十而当月只有 29 天 → 落到当月最后一天

### `:core:database` — 日期怎么存

- 只有「日」语义的列（纪念日、经期起止）存 **epochDay**
- 有真实时刻的列（待办截止时间、各种 `*_at`）存 **epochMilli**

存毫秒表示纯日期会带上一个假的时刻，跨时区或夏令时时可能整体偏一天。

全局字段约定（为将来同步预留，现在就要有，后补代价极大）：
`uuid` / `created_at` / `updated_at`，需要软删除的表另加 `deleted_at`。
软删除还有个免费的好处：撤销删除是无损的。

### `:feature:todo` — 参考实现

新增 feature 照抄这个模块的目录结构：`data/` `list/` `edit/` `home/` `navigation/` `ui/`。

- 新建与编辑**共用一个页面**，`id = 0` 表示新建，不值得为此多一条路由
- 重复任务完成后生成**新条目**而不是改旧条目日期，这样「已完成」视图能看到完整历史
- 下一次从**原定截止时间**推算，不是完成时间——否则拖延几天会把整条链往后推
- 保存走**读改写**而非整体 REPLACE：`uuid` / `createdAt` / `done` 不属于表单，
  整体构造会把它们悄悄清掉（uuid 丢了将来同步就对不上）

### `:feature:anniversary`

- 重复类型存字符串不存枚举（`ONCE` / `YEARLY` / `CUMULATIVE`），加新类型不用做迁移
- 农历纪念日：`date` 列存**用户输入那天的公历日期**，农历月日在读取时换算。
  只需一个日期字段，用户切换公历/农历也不用重新输入
- 排序在**内存里**做不在 SQL：排序键要经过农历换算与「每年重复」推算，写不成 SQL 表达式。
  几十条的量级，代价可忽略
- 累计型的下一个里程碑：**整百天与周年取更近的那个**。
  只倒数整百天会漏掉「三周年」，只倒数周年会错过「在一起 1000 天」
- 置顶是**单选**，写入后统一收敛，避免出现两条置顶

### `:feature:period`

预测算法刻意保持简单（PRD 3.2 V1）：`下次开始 = 最近一次开始 + round(近 6 次周期均值)`。
不做加权、不做复杂建模——样本量本来就只有个位数，复杂模型只会放大噪声，
却让用户以为结果更准。

三处加固（都有测试覆盖，`PeriodPredictionTest` 9 条）：

1. **「进行中」设 15 天上限**。忘记点「结束」远比经期真的持续半个月常见，
   不设上限的话一次漏记会让首页永远显示「经期第 87 天」
2. **可靠性阈值比 PRD 下限严一档**：要求至少 3 个间隔才算 `reliable`。
   只有 1 个间隔时「平均」就等于那一次本身，把单次波动原样当预测，仍然该提示「样本不足」
3. 剔除 10~90 天之外的异常间隔（补录历史时录错年份的典型症状）

日历上**实际记录用实心色块、预测用虚线圈**——这两者绝不能长得像，
否则用户会把预测当成已发生的事实。

### `:feature:note` - M3 笔记

- **FTS 用 contentEntity 模式而不是 standalone 表**：`NoteFtsEntity` 通过 `@Fts4(contentEntity = NoteEntity::class)` 关联主表，Room 自动建外部内容表 + 触发器同步主表到 FTS。改 NoteEntity 不需要手动维护 FTS 同步逻辑。搜索时用 `rowid MATCH` JOIN 回主表，不是普通 SELECT
- **Photo Picker 不申请权限**：`PickVisualMedia` 是系统级 Activity，返回的 `content://` Uri 默认只对当前进程有效。要持久化（重启后还能读）必须 `contentResolver.takePersistableUriPermission(uri, FLAG_GRANT_READ_URI_PERMISSION)`，否则重启后 Uri 失效图片就丢。读取时 `BitmapFactory` 配 `inSampleSize` 防 OOM
- **MarkdownRenderer 是纯字符串解析器**：不依赖 Compose，输入 Markdown 文本输出 `AnnotatedString`，可以单测。`NoteMarkdownTest` 14 条覆盖各种语法边界（标题/粗体/斜体/列表/代码块/链接/分割线）
- **撤销删除走 Channel 而不是 StateFlow**：Snackbar 的显示是一次性事件，用 `Channel<UndoEvent>` + `receiveAsFlow()`，避免配置变更后重复弹
- **图片路径列表用 `` (U+0001) 分隔**：ASCII Unit Separator，文件名禁用字符，路径里不会出现，分隔安全。不用 JSON 序列化库，`:core:database` 没引入 kotlinx.serialization，为这一个字段拉依赖不划算

### `:feature:question` - M4 疑问收集箱

- **状态机存 TEXT 字符串不存枚举**：`QuestionStatus` 枚举有 `stored: String` 属性，存 `"OPEN"` / `"RESOLVED"` / `"ARCHIVED"`。加新状态不需要迁移（与 `AnniversaryEntity.repeatType` 同一套约定）。`from(s: String?)` 容错未知值回退到 `OPEN`
- **状态转换的不变式**（关键，Repository 用读改写强制）：
  - 进入 RESOLVED 时 `resolved_at = now`；离开 RESOLVED 时 `resolved_at = null`
  - `answer` 字段一旦写入**永不清空**——切回 OPEN 时 answer 保留（只是 UI 禁用），再切回 RESOLVED 不丢已写答案
  - `convertToNote` 后**状态保持 RESOLVED**，不自动归档（用户可能想多次转笔记或自己手动归档）
- **`canSave` 是唯一的硬约束**：content 非空 + RESOLVED 必须有 answer。其他状态转换全部允许，不强加业务规则
- **「转为笔记」走 NoteWriter 契约**：`QuestionRepository` 注入 `NoteWriter`（在 `:core:common` 定义，`:feature:note` 的 `NoteModule` 里 `@Binds` 到 `NoteRepository`）。`:feature:question` 不依赖 `:feature:note`，Hilt 在运行时自动解析。生成的笔记内容是 `# 疑问\n\n${content}\n\n# 解答\n\n${answer}`，标签追加 `"疑问"` 便于将来反查
- **首页随机卡片用 refresh trigger 模式**：`ORDER BY RANDOM() LIMIT 1` 只在表变更时重新 emit，点 refresh icon 必须通过 `_refresh.value++` + `flatMapLatest` 重订阅触发，否则点完没反应。从编辑页返回时也会自动刷新（用户可能已解决该疑问）
- **列表分组在内存里做**：Repository 一次查全部（不过滤 `deleted_at`），ViewModel 按 status 分组。一次查询比三条分支查询少 IO，量级小（预期不超过几百条）代价可忽略
- **V1 不上 FTS**：用 LIKE 搜索 content/context，量级够用。将来需要再加 v5 迁移补 FTS（参考 MIGRATION_2_3）

### `:app` - 组装层（底部导航 + 全局 FAB，PRD 3.11）

- **`MyApp.kt` 用 Box 叠层不用 Scaffold.bottomBar**：Haze 毛玻璃需要 bottomBar 与 content 的 bounds 交叠才能采样（见第五节坑 #10）。结构是 `Box { AppNavHost(hazeSource) → MyAppBottomBar(hazeEffect) → MultiActionFab }`
- **顶级目的地识别用字符串匹配**：`toRoute<Route>()` 对 sealed interface 会崩（见第五节坑 #12），改用 `currentEntry?.destination?.route` 与 `dest.route::class.qualifiedName` 比较
- **`MultiActionFab` 状态提升**：`expanded` 由 `MyApp` 持有，组件本身不依赖 activity-compose，`BackHandler` 拦截放在 `MyApp`。保持 `:core:designsystem` 纯 UI
- **`LocalBottomBarHeight` CompositionLocal**：底栏可见时由 `MyApp` 用 `onGloballyPositioned` 测量实际高度（含 `navigationBarsPadding`）注入，各列表页 Scaffold 读它让 FAB 上抬避开底栏。底栏隐藏时归零
- **FAB 只在首页显示**：各列表页（NoteList/QuestionList/TodoList/AnniversaryList）保留各自 FAB，不显示全局 FAB。NoteList/Settings 是顶级目的地删返回箭头，QuestionList/TodoList/AnniversaryList 是二级页面保留返回箭头
- **占位页**：`PlaceholderScreen` 用于记账/资讯 tab（M5/M6/M8 未落地），「记一笔」FAB 子按钮用 Toast 占位
