## 什么是魔术/魔法方法

“魔术方法”（Magic Methods）或“魔法方法”是 Python 中一类特殊的方法，它们的名字以双下划线（`__`）开头和结尾，例如 `init`、`str`、`add` 等。由 Python 解释器自动调用。



## 装饰器

Python 装饰器的本质是语法糖（syntactic sugar），其核心思想是**高阶函数** \+ **闭包**。装饰器通常**是一个高阶函数——它接收一个函数，并返回一个新的函数**。



Python中的装饰器它允许在不修改原函数代码的前提下，动态地给函数或类增加额外的功能。你可以把它想象成一个“包装器”或“增强器”。类似Spring的aop\+自定义注解



装饰器应用场景，例如：

- 日志记录 \(Logging\)：记录函数的调用信息。

- 性能测试 \(Timing\)：测量函数执行时间。

- 权限检查 \(Authorization\)：检查用户是否有权限执行某个操作。

- 缓存 \(Caching\)：缓存函数的返回结果，避免重复计算（如 `functools.lru_cache`）。

- 输入验证 \(Validation\)：验证函数参数的有效性。

- 重试机制 \(Retry\)：在函数执行失败时自动重试。

- Flask/Django 路由：在 Web 框架中，`@app.route('/path')` 就是典型的装饰器用法，将 URL 路径映射到处理函数。

## 迭代器

同时实现了 `iter()` 和 `next()` 方法的对象；都可以被称为迭代器；像`list`, `str`, `dict`, `set`, `range`, 文件对象等都属于可被迭代对象。

- 调用 `__next__()` 返回下一个元素；

- 没有更多元素时抛出 `StopIteration` 异常；

- 只能向前遍历一次（不可逆、不可重复）；

- 惰性计算（不一次性加载所有数据到内存）。

示例代码：

```Python
it = iter([1, 2, 3])  # 获取迭代器
print(next(it))  # 1
print(next(it))  # 2
print(next(it))  # 3
print(next(it))  # StopIteration
```



## 高阶函数

在 Python 中，**高阶函数**是指满足以下任一条件的函数：

1. 接受一个或多个函数作为参数；

2. 返回一个函数作为结果。

装饰器的定义就符合：例如：

```Python
def greet_decorator(func):
    def wrapper():
        print("开始执行")
        func()
        print("执行结束")
    return wrapper

# greet_decorator 就是一个高阶函数

@greet_decorator
def greet2():
    print("你好，传智播客")
```

## 闭包

闭包是指一个内部函数“记住”并可以访问其外部作用域中的变量，即使外部函数已经执行完毕。

换句话说，闭包 = 内部函数 \+ 外部作用域的自由变量（free variables）。



## 数据结构或集合类型

列表 \(List\)、元组 \(Tuple\)、集合 \(Set\) 和 字典 \(Dictionary\)。此外，`字符串 (String)` 也可以被视为一种特殊的容器（字符序列）

1. **列表 \(List\) \- ****`list`**

    - **有序** \(Ordered\): 元素在列表中有确定的位置（索引），可以通过索引访问（`list[0]`）。

    - **可变** \(Mutable\): 可以修改列表本身的内容，例如添加（`append`, `insert`）、删除（`remove`, `pop`）、修改（`list[0] = new_value`）元素。

    - **允许重复元素**: 同一个值可以出现多次。

    - **允许不同数据类型**: 列表中的元素可以是任意类型（整数、字符串、其他列表、字典等）。

    - **适用场景**: 存储需要频繁修改、保持顺序、可能包含重复项的元素序列。例如：购物车商品列表、任务列表、一系列计算结果。

2. **元组 \(Tuple\) \- ****`tuple`**

    - 有序 \(Ordered\): 元素有索引，可以通过索引访问（`tuple[0]`）。

    - 不可变 \(Immutable\): 一旦创建，其内容（元素的值和顺序）不能被修改。不能添加、删除或更改元素。

    - 允许重复元素: 同一个值可以出现多次。

    - 允许不同数据类型: 元素可以是任意类型。

    - **适用场景**: 存储不应被修改的数据，例如：坐标点 `(x, y)`、日期 `(year, month, day)`、函数的多个返回值、作为字典的键（因为不可变）。由于不可变性，元组通常比列表更轻量，性能稍好。

3. **集合 \(Set\) \- ****`set`**

    - 无序 \(Unordered\): 元素没有固定的顺序，不能通过索引访问（`set[0]` 会报错）。

    - 可变 \(set\) / 不可变 \(frozenset\): `set` 类型可以添加（`add`）、删除（`remove`, `discard`）元素。`frozenset` 创建后不可变。

    - 不允许重复元素: 集合会自动去重。`{1, 2, 2, 3}` 实际存储为 `{1, 2, 3}`。

    - 元素必须是可哈希的 \(Hashable\): 通常意味着元素必须是不可变的（如 `int`, `float`, `str`, `tuple`）。列表、字典、其他集合不能作为集合的元素。

    - **适用场景**: 需要去重、进行集合运算（交集、并集、差集）、或需要快速检查成员是否存在的场景。例如：找出两个列表的共同元素、去除列表中的重复项、记录用户ID（确保唯一性）。

4. **字典 \(Dictionary\) \- ****`dict`**

    - 有序 \(Ordered\): 从 Python 3\.7\+ 开始，字典保证了插入顺序（之前版本是无序的）。

    - 可变 \(Mutable\): 可以添加新的键值对、修改现有键的值、删除键值对。

    - 键 \(Key\) 唯一: 每个键在字典中必须是唯一的。如果重复赋值同一个键，后面的值会覆盖前面的值。

    - 键必须是可哈希的 \(Hashable\): 键必须是不可变类型（如 `int`, `str`, `tuple`）。值 \(`Value`\) 可以是任意类型，包括其他容器（如列表、字典）。

    - **适用场景**: 存储键值对 \(Key\-Value Pairs\) 数据，通过键来快速查找、存储和组织相关数据。这是最常用的数据结构

5. **字符串 \(String\) \- ****`str`**** \(作为字符容器\)**

    - 有序 \(Ordered\): 字符有索引，可以通过索引访问（`s[0]`）。

    - 不可变 \(Immutable\): 不能修改字符串本身的内容。任何“修改”操作（如拼接）都会创建一个新的字符串对象。

    - 允许重复字符: 字符可以重复。

## lambda表达式

`lambda` 表达式（又称匿名函数）是 Python 中一种创建小型、简单、一次性函数的简洁方式。允许在需要函数对象的地方快速定义一个函数，而无需使用 `def` 语句进行命名。

**特点**

1. 匿名性: `lambda` 函数没有名字。它通常被赋值给一个变量，或者直接作为参数传递给其他函数。

2. 单一表达式: **只能包含一个表达式**，不能有多条语句。

3. 自动返回: 表达式的结果会自动作为函数的返回值，**不需要也不能写 ****`return`**** 语句**。

4. 作用域: `lambda` 函数可以访问其定义所在作用域的变量（类似于闭包）。

## 线程与协程的区别

线程由操作系统内核调度，是“抢占式多任务”；协程由用户程序（或运行时）调度，是“协作式多任务”。

**协程**没有创建新线程，所有任务在一个线程的事件循环中交替执行。

协程示例如下：

```Python
import asyncio

async def task(n):
    await asyncio.sleep(1)  # 异步非阻塞
    print(f"Task {n} done")

async def main():
    # 并发运行 3 个协程
    await asyncio.gather(task(0), task(1), task(2))

asyncio.run(main())
# 总耗时 ≈ 1 秒（单线程内并发）
```

## Python 单例

在 Python 中实现单例模式（Singleton Pattern），核心目标是：确保一个类只有一个实例，并提供一个全局访问点。

**方式一**：使用 `__new__` 重写

```Python
class Singleton:
    _instance = None
    def __new__(cls, *args, **kwargs):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance
*# 测试  注意 Singleton 是类名；随便起名字*
s1 = Singleton()
s2 = Singleton()
print(s1 is s2)  *# True   *

# __new__方法中的 cls 表示当前这个类； __new__方法比 __init__方法早执行，所以不能使用self ， self是当前实例对象
```

**方式二**：使用装饰器

```Python
def singleton(cls):
    instances = {}
    def get_instance(*args, **kwargs):
        if cls not in instances:
            instances[cls] = cls(*args, **kwargs)
        return instances[cls]
    return get_instance

@singleton
class MyClass:
    def __init__(self, value):
        self.value = value

a = MyClass(10)
b = MyClass(20)
print(a is b)        # True
print(a.value)       # 10（第二次调用不会重新初始化）
```

## 单例存在的问题

在多线程环境下可能出问题（多个线程同时检查 `_instance is None`）。

解决方法：可以加锁；在判断单例是否为None之前；使用` 类名._lock `进行加锁

```Python
import threading

class ThreadSafeSingleton:
    _instance = None
    _lock = threading.Lock()

    def __new__(cls, *args, **kwargs):
        if cls._instance is None:
            with **cls._lock**:
                # 双重检查（Double-checked locking）
                if cls._instance is None:
                    cls._instance = super().__new__(cls)
        return cls._instance
```

## Python的GIL机制

## 生成器yield

`yield` 是 Python 中用于定义 生成器（Generator） 的关键字，它让函数变成一个可迭代的、惰性求值的对象。

带有 `yield` 的函数不再是一个普通函数，而是一个“生成器函数”；调用它不会立即执行函数体，而是返回一个“生成器对象”。

需要“按需生成数据”而不是“一次性返回所有数据”时，就该用 `yield`。

```Python
def my_generator():
    yield 1
    yield 2
    yield 3

# 使用
for value in my_generator():
    print(value)  *# 1, 2, 3*
```

## ASGI

ASGI 全称 Asynchronous Server Gateway Interface **异步服务器网关接口**。定义了一套标准接口规范，用于连接 Web 服务器和应用程序框架，实现异步处理请求和响应。ASGI 的目标是提供高性能、可伸缩和灵活的 Web 应用程序开发体验。



**为什么需要 ASGI？**

传统的 Python Web 服务器（如 WSGI）在处理请求时通常采用同步的方式，即每个请求都会阻塞服务器线程，导致服务器无法同时处理大量并发请求。而 ASGI 规范引入了异步编程模型，使得服务器能够以非阻塞的方式处理请求，实现更好的并发性能和扩展性。

ASGI 还允许使用异步的应用程序框架，例如使用异步函数 async、协程或异步 IO asyncio 操作来处理请求。这种异步编程模型可以提供更高的性能，并允许处理复杂的并发操作，如长轮询、WebSocket 等。

- 使用异步 I/O 库（httpx, asyncpg 等） I/O 密集型操作必须用异步（如 HTTP 请求、DB 查询、文件读写）      

- 避免在 async 中调用同步阻塞函数        

- 部署时使用多 worker（Gunicorn \+ Uvicorn）；worker 数量建议：`CPU 核心数 × (1~2)`（I/O 密集型可略高）

- 启用 GZip 压缩 ；减少网络传输体积（尤其对 JSON 大数据）

- 数据库使用连接池 \+ 异步驱动

- 热点数据加 Redis 缓存；缓存热点数据（如用户信息、配置）；

- 接口添加限流保护

- 静态资源由 Nginx/CDN 处理

- 关闭 debug 模式

    ```Python
    app = FastAPI(debug=False)  *# 生产环境必须关闭！*
    ```

## FastAPI实现异步处理

FastAPI 原生支持异步编程，其底层基于 Starlette（ASGI 框架），能高效处理高并发 I/O 密集型任务。可以 使用 `async/await` 实现异步处理；方式参考如下：

```Python
from fastapi import FastAPI

app = FastAPI()

@app.get("/async-demo")
async def async_demo():
    # 这里必须 await 异步操作
    result = await some_async_function()
    return {"result": result}
```

## 协程

Python中通过使用 async 和 await 的异步代码的函数被概括为"协程"（coroutine function）

- `async def` 定义的是 协程函数，

- 调用后得到的是 协程对象，

- 两者常被统称为“协程”。



## FastAPI的路由

在 FastAPI 中，Route（路由） 是指**将一个** **HTTP 请求方法** \+ **URL 路径** **映射到一个** **处理函数**（也叫路径操作函数）** 的机制**。它是 Web 应用接收用户请求并返回响应的核心方式。

## FastAPI的Depends

`Depends` 是 FastAPI 提供的一个类（来自 `fastapi` 模块），用于在路径操作函数（即路由处理函数）中声明依赖项。FastAPI 会在调用主函数前，自动解析并注入这些依赖。也就是说，在执行某个函数之前，调用`Depends`指定的函数。

示例：

```Python
from fastapi import Depends, HTTPException, Header

def verify_token(authorization: str = Header(...)):
    if authorization != "Bearer secret123":
        raise HTTPException(status_code=401, detail="Invalid token")
    return {"user_id": 123}

@app.get("/profile")
def get_profile(user=Depends(verify_token)):
    return {"hello": f"user {user['user_id']}"}
```

## Milvus向量数据库中，数据存储的格式是什么？

Milvus 将数据存储在分层的文件系统中，主要格式包括：

1. 向量数据：使用列式存储格式（如 Apache Arrow），高效存储原始向量。同时，会将构建好的向量索引文件（如 HNSW 图、IVF 聚类中心）单独存储，用于加速检索。

2. 标量数据：实体的属性字段（如 ID、标签、数值）通常以 Parquet 或 JSON 等格式存储，便于高效读取和过滤。

3. 元数据：使用 etcd 存储集群配置、集合（Collection）Schema、索引状态等轻量级元信息。

4. 日志：通过 Pulsar 或 Kafka 存储操作日志（WAL），保证数据的持久性和可重放性，用于数据恢复和增量同步。



## 向量数据库的混合精度索引怎么做

1. 高精度存储，低精度索引：

    - 原始向量（如 float32）被完整存储，保证最终重排序的精度。

    - 在构建索引时，使用量化算法（如乘积量化 PQ、标量量化 SQ）将高维向量压缩成低精度的表示（如 uint8 甚至二进制码）。

    - 搜索时，先用低精度的索引进行快速粗筛（Fast Scan），从海量数据中找出一个较小的候选集。

2. 分层检索（Hybrid Search）：

    - 将向量相似性搜索与标量过滤结合。

    - 首先，通过标量条件（如时间范围、类别标签）在索引中快速过滤出一个子集。

    - 然后，只在这个较小的子集上执行向量相似性搜索。

    - 这避免了对全量数据进行昂贵的向量计算，显著提升了效率。

3. 多阶段排序：

    - 第一阶段（粗排）：使用低精度、快速的近似算法（如基于量化索引的搜索）得到 Top\-K 候选。

    - 第二阶段（精排）：对候选集使用原始的高精度向量和精确距离计算（如 float32 的内积）进行重排序，保证最终结果的准确性。

## 深度学习与机器学习的区别

深度学习（Deep Learning） 是 机器学习（Machine Learning） 的一个子集；深度学习是机器学习的一种方法，基于人工神经网络，特别是深层神经网络。

**机器学习**：适用在数据量小、特征明确、需要可解释性；资源有限，无GPU

**深度学习**：适用在数据量大（尤其是图像、语音、文本）、特征复杂；追求高精度（如 ImageNet、机器翻译）



## 卷积神经网络（CNN）

卷积神经网络（CNN）是一种专门用于处理网格状数据（如图像、音频、视频）的深度学习模型，其核心思想是通过局部感知和权值共享来高效提取空间特征。

主要组成部分：

1. 卷积层（Convolutional Layer）：

    - 使用可学习的卷积核（滤波器）在输入数据（如图像）上滑动，进行局部区域的加权求和。

    - 每个卷积核能检测一种特定的局部特征（如边缘、纹理）。

    - 权值共享：同一个卷积核在整个输入上使用相同的参数，大大减少了参数量。

2. 激活函数：

    - 在卷积后通常加入非线性激活函数（如 ReLU），引入非线性能力，使网络能学习复杂模式。

3. 池化层（Pooling Layer）：

    - 对特征图进行下采样（如最大池化、平均池化），降低数据维度，减少计算量，同时增强特征的平移不变性。

4. 全连接层（Fully Connected Layer）：

    - 通常在最后几层，将前面提取到的高维特征“展平”后连接，用于最终的分类或回归。

工作流程：

输入图像 → 多个“卷积\+激活\+池化”组合 → 提取从低级（边缘）到高级（物体部件、整体）的特征 → 全连接层 → 输出预测结果。

CNN 因其强大的特征提取能力，被广泛应用于图像分类、目标检测、语义分割等计算机视觉任务，是深度学习在视觉领域成功的关键。

- CNN 模型结构

    - 卷积层（Conv）：提取边缘、纹理等特征

    - 池化层（Pool）：缩小尺寸，保留重要信息

    - 全连接层（FC）：最终分类

## 激活函数

激活函数是神经网络中的核心组件，用于为神经元的输出**引入非线性，让神经网络可以进行非线性转换；**使网络能够学习和逼近复杂的非线性函数。如果没有激活函数，多层网络将退化为线性模型。

- 引入非线性：使神经网络能够拟合任意复杂的函数（万能近似定理）。

- 控制输出范围：如将输出压缩到 \[0,1\] 或 \[\-1,1\]，便于优化和解释。

- 决定神经元是否激活：根据输入加权和，判断是否“ firing”。

> 如果没有激活函数，多层神经网络 = 单层线性变换（因为线性组合的线性组合仍是线性的）。
> 
> 

## 常见的激活函数

1. **ReLU（Rectified Linear Unit）**：

    - 公式：f\(x\)=max⁡\(0,x\)*f*\(*x*\)=max\(0,*x*\)

    - 优点：计算简单，能有效缓解梯度消失问题，训练速度快。

    - 缺点：存在“死亡 ReLU”问题（负数输出为0，梯度为0）。

    - 最常用于隐藏层。

2. **Sigmoid**：

    - 公式：f\(x\)=11\+e−x*f*\(*x*\)=1\+*e*−*x*1

    - 输出范围：\(0, 1\)

    - 优点：可解释为概率。

    - 缺点：容易导致梯度消失，输出不是零中心。

    - 常用于二分类的输出层。

3. **Tanh（双曲正切）**：

    - 公式：f\(x\)=ex−e−xex\+e−x*f*\(*x*\)=*ex*\+*e*−*xex*−*e*−*x*

    - 输出范围：\(\-1, 1\)

    - 优点：输出是零中心，比 Sigmoid 梯度更强。

    - 缺点：仍有梯度消失问题。

    - 可用于隐藏层。

4. **Softmax**：

    - 公式：f\(zi\)=ezi∑jezj*f*\(*zi*\)=∑*jezjezi*

    - 输出范围：\(0, 1\)，且所有输出之和为 1。

    - 用途：多分类任务的输出层，输出类别概率分布。

5. **Leaky ReLU / Parametric ReLU**：

    - 公式（Leaky）：f\(x\)=max⁡\(0\.01x,x\)*f*\(*x*\)=max\(0\.01*x*,*x*\)

    - 优点：解决了 ReLU 的“死亡”问题，允许小的负数输出。

    - 变种如 PReLU 将斜率作为可学习参数。

6. **GELU（Gaussian Error Linear Unit）**：

    - 公式：f\(x\)=xΦ\(x\)*f*\(*x*\)=*x*Φ\(*x*\)，其中 Φ\(x\)Φ\(*x*\) 是标准正态分布的累积分布函数（实际计算常用近似）。

    - 优点：在 Transformer 等模型中表现优异，被认为是 ReLU 的平滑替代。

    - 广泛用于 BERT、GPT 等大模型的隐藏层。

选择哪种激活函数取决于具体任务和网络结构，但 ReLU 及其变种是目前最主流的选择。



- **隐藏层首选**：ReLU、GELU（尤其在Transformer中）。

- **输出层**：Sigmoid（二分类）、Softmax（多分类）

## 梯度

梯度是多元函数在某一点处的方向导数中变化率最大的方向，它是一个向量，包含了函数在各个自变量方向上的偏导数。梯度是一个向量，既有大小（模长），也有方向。

在训练模型时，我们希望最小化损失函数 L\(θ\)，其中 θ=\(θ1,θ2,…,θn\) 是模型参数。

梯度告诉我们：每个参数应该如何调整，才能最快地降低损失。

## 梯度下降

梯度下降是一种用于优化机器学习和深度学习模型的核心迭代算法，其目标是最小化一个损失函数（Loss Function）的值。

最基础的分类方式：

- 批量梯度下降（Batch Gradient Descent, BGD）：

    - 计算方式：每次参数更新都使用整个训练集计算损失函数的梯度。

    - 优点：梯度方向准确，收敛稳定。

    - 缺点：当数据量大时，计算开销巨大，速度慢。

    - 公式：θ=θ−η∇θJ\(θ;X,y\)*θ*=*θ*−*η*∇*θJ*\(*θ*;*X*,*y*\)，其中 X,y*X*,*y* 是全部数据。

- 随机梯度下降（Stochastic Gradient Descent, SGD）：

    - 计算方式：每次更新只使用一个随机样本计算梯度。

    - 优点：计算快，内存占用小，能跳出局部极小。

    - 缺点：梯度方向噪声大，更新路径震荡，收敛不稳定。

    - 公式：θ=θ−η∇θJ\(θ;x\(i\),y\(i\)\)*θ*=*θ*−*η*∇*θJ*\(*θ*;*x*\(*i*\),*y*\(*i*\)\)，其中 \(x\(i\),y\(i\)\)\(*x*\(*i*\),*y*\(*i*\)\) 是单个样本。

- **小批量梯度下降**（Mini\-batch Gradient Descent）：

    - 计算方式：每次更新使用一小批样本（如 32、64、128 个）计算梯度。

    - 优点：结合了 BGD 和 SGD 的优点，计算效率高，利用 GPU 并行，收敛相对稳定。

    - 缺点：需要选择合适的批量大小（batch size）。

    - 现状：这是深度学习中**最常用的标准方法**。



## 梯度下降优化

在小批量梯度下降的基础上，引入了自适应机制来提升性能：

- 动量法（Momentum）：

    - 引入“动量”概念，模拟物理中的惯性。

    - 更新时不仅考虑当前梯度，还考虑之前的更新方向，能加速收敛并减少震荡。

    - 公式包含速度项：v=γv\+η∇θJ\(θ\)*v*=*γv*\+*η*∇*θJ*\(*θ*\)，然后 θ=θ−v*θ*=*θ*−*v*。

- Nesterov 加速梯度（NAG）：

    - Momentum 的改进版，先根据历史动量“往前看一步”，再计算梯度。

    - 能更智能地调整方向，避免冲过头，收敛更快。

- Adagrad：

    - 自适应地为每个参数调整学习率。

    - 频繁更新的参数（梯度大）学习率自动变小，稀疏特征的参数学习率保持较大。

    - 缺点：学习率会单调递减，后期可能过小。

- RMSProp：

    - Adagrad 的改进，使用指数加权移动平均来计算梯度的二阶矩。

    - 解决了 Adagrad 学习率过早衰减的问题。

- **Adam**（Adaptive Moment Estimation）：

    - 目前**最流行的优化器之一**。

    - 结合了 Momentum（一阶矩估计）和 RMSProp（二阶矩估计）的优点。

    - 为每个参数自适应调整学习率，收敛快，性能稳定。

- AdamW：

    - Adam 的改进版，修正了权重衰减（L2 正则化）的实现方式，能更好地泛化。



## 梯度消失问题及处理方法

在深度神经网络（尤其是早期的深度网络）中，使用反向传播算法计算梯度时，靠近输入层的浅层网络的梯度值变得非常小（趋近于 0），导致这些层的参数几乎无法更新，模型训练停滞。

**原因**：

- 激活函数的导数小于 1：如 Sigmoid（导数最大为 0\.25）或 Tanh。

- 深层网络中，梯度是通过链式法则连乘各层的导数得到的。

- 当多个小于 1 的数连续相乘时，结果会指数级衰减，最终趋近于 0。

**后果**：

- 浅层网络无法有效学习特征。

- 网络性能差，训练效率低。

**解决方法**

1. 使用合适的激活函数：

    - ReLU（Rectified Linear Unit）：f\(x\)=max⁡\(0,x\)*f*\(*x*\)=max\(0,*x*\)，其导数在正区间为 1，避免了梯度在正区间的连乘衰减。

    - Leaky ReLU / Parametric ReLU：解决 ReLU 的“死亡神经元”问题。

    - GELU：在 Transformer 等大模型中广泛使用。

2. 权重初始化：

    - 不恰当的初始化会导致激活值过大或过小，加剧梯度消失。

    - 使用 Xavier 初始化（适合 Sigmoid/Tanh）或 He 初始化（适合 ReLU）等方法，使每层的输出方差保持稳定。

3. 批量归一化（Batch Normalization）：

    - 对每层的输入进行归一化（减均值、除标准差），使数据分布稳定。

    - 缓解内部协变量偏移，有助于梯度稳定传播。

4. 残差连接（Residual Connections / Skip Connections）：

    - 如 ResNet 中的“跳跃连接”，允许梯度直接绕过若干层。

    - 公式：y=F\(x\)\+x，即使 F\(x\) 的梯度消失，*x* 的梯度仍可直接传递。

    - 是解决极深网络梯度问题的关键突破。

5. 使用更先进的优化器：

    - 如 Adam、RMSProp 等自适应学习率方法，能根据梯度历史调整更新步长，缓解梯度小带来的影响。

## 梯度爆炸问题及处理方法

在深度神经网络或循环神经网络（RNN）中，反向传播时计算的梯度值变得非常大（趋于无穷），导致模型参数更新幅度过大，造成数值溢出或训练不稳定。

**原因**：

- 当网络中某些层的权重较大，且激活函数的导数也较大时，链式法则中的梯度会连乘并指数级增长。

- 尤其在深层网络或长序列的 RNN 中，梯度经过多层传播后可能急剧放大。

**后果**：

- 参数更新剧烈，损失函数剧烈震荡。

- 可能出现 `NaN`（非数字）值，导致训练失败。

**解决方法**

1. **梯度裁剪**（Gradient Clipping）：

    - 最常用、最直接的方法。

    - 设定一个阈值（如 1\.0 或 5\.0），当梯度的范数（如 L2 范数）超过该阈值时，将梯度按比例缩放至阈值以内。

    - 广泛应用于 RNN、Transformer 等模型。

2. 权重初始化：

    - 使用合适的初始化方法，避免初始权重过大。

    - 如 Xavier 初始化、He 初始化，能有效控制前向传播和反向传播时信号的尺度。

3. 使用批量归一化（Batch Normalization）：

    - 对每层的输入进行归一化，使数据分布稳定，减少梯度爆炸的风险。

4. 简化网络结构：

    - 减少网络深度或隐藏层大小，降低梯度连乘的层数。

    - 在 RNN 中，可使用更稳定的变体如 LSTM 或 GRU，它们通过门控机制缓解了长期依赖中的梯度问题。

5. 降低学习率：

    - 如果梯度很大，使用过大的学习率会加剧参数更新的不稳定性。

    - 适当降低学习率可以缓解爆炸带来的影响。

6. 使用残差连接（Residual Connections）：

    - 在深层网络中，残差连接允许梯度直接“跳跃”传播，避免在长链中不断放大。

## 梯度裁剪

**梯度裁剪**（Gradient Clipping）是一种在训练深度神经网络时用于**防止梯度爆炸（Exploding Gradient）**问题的技术。主要是当梯度的“规模”（通常用范数衡量）超过某个预设阈值时，将其按比例缩小，使其不超过该阈值。



**为什么需要梯度裁剪？**

在深层网络（尤其是循环神经网络 RNN、Transformer）中，反向传播计算梯度时，梯度可能由于链式法则的连乘而变得非常大，导致：

- 参数更新幅度过大。

- 损失函数剧烈震荡。

- 出现 `NaN` 值，训练失败。

梯度裁剪通过限制梯度的大小，确保训练过程稳定。



**常见方法**

**1\. 按值裁剪（Clip by Value）**

- 将梯度的每个元素限制在一个范围内，如 `[-1, 1]`。实现简单，开销小

**2\. 按范数裁剪（Clip by Global Norm） ✅ 最常用**

- 计算所有参数梯度的全局范数（如 L2 范数）。

- 如果范数大于阈值，则将所有梯度按相同比例缩放。

## 学习率

学习率（通常记作 η（伊塔）或 `lr`）控制着模型参数在每次优化更新时的**步长**大小。



**如何选择学习率？**

- 常见值：`0.1`, `0.01`, `0.001`, `0.0001`

- 深度学习中常用 `1e-3`（**0\.001**）作为 Adam 的默认值。



## 学习率与梯度的关系

学习率（Learning Rate）和梯度（Gradient）是梯度下降优化算法中的两个核心要素，它们共同决定了模型参数的更新方式和训练过程的稳定性。

- 梯度决定了参数更新的方向。

- 学习率 是一个正数，控制每次参数更新的步长大小。

## 残差连接

**残差连接（Residual Connection）**，也称为跳跃连接（Skip Connection），用于深度网络中的缓解梯度消失和解决性能退化问题。

传统网络学习的是：`y=F(x)`

残差网络学习的是：`y=F(x)+x`

其中：

- x是输入。

- F\(x\) 是网络需要学习的残差函数（即输入与期望输出之间的差异）。

- F\(x\)\+x 是最终输出。

👉 本质：让网络去学习`输入与输出之间的差值`，而不是直接学习完整的输出。



**为什么有效？**

1. **缓解梯度消失：**

    - 反向传播时，梯度可以通过跳跃连接直接传回浅层，避免在深层网络中因连乘导致梯度衰减。

    - 即使 F\(x\)*F*\(*x*\) 的梯度很小，x*x* 的梯度仍可直接传递。

2. **解决性能退化问题：**

    - 理论上，更深的网络不应比浅层网络性能差（至少可以学习恒等映射）。

    - 但传统深层网络训练后性能反而下降。

    - 残差连接使得网络在 F\(x\)=0*F*\(*x*\)=0 时自动退化为恒等映射，保证了深度增加不会降低性能。



## 损失函数

损失函数（Loss Function）用于衡量模型的**预测值与真实值之间的差异**或误差。

**核心作用**

- 损失函数的值越小，表示模型的预测结果越接近真实结果。

- 模型训练的目标就是通过优化算法（如梯度下降）最小化损失函数的值，从而找到最优的模型参数。

## 常见的损失函数

1. **回归任务（预测连续值）**

- 均方误差（**MSE**, Mean Squared Error）：最常用，对异常值敏感。

- 平均绝对误差（**MAE**, Mean Absolute Error）：对异常值更鲁棒，但梯度不连续。

2. **分类任务**

- **交叉熵损失**（Cross\-Entropy Loss）：

    - 二分类（常与 Sigmoid 配合）：

    - 多分类（常与 Softmax 配合）：

    - 优点：惩罚预测概率远离真实标签的情况，适合概率输出。

- **Hinge Loss**：主要用于支持向量机（SVM），强调分类间隔。



## 优化算法/优化器有哪些

深度学习中，优化算法用于最小化损失函数，更新模型参数。优化算法是模型训练的“引擎”，选择合适的算法能显著提升训练效率和模型性能。以下是几种主流优化算法：

1. **SGD（随机梯度下降）**

- 原理：每次参数更新只使用一个样本（或一个小批量）计算梯度。

- 优点：

    - 计算快，内存占用小。

    - 能跳出局部极小（因梯度噪声）。

- 缺点：

    - 更新路径震荡大，收敛不稳定。

    - 学习率需手动调整。

> ✅ 基础方法，适合大规模数据。
> 
> 

---

2. **Momentum（动量法）**

- 原理：引入“动量”概念，模拟物理中的惯性。梯度更新时积累历史梯度方向。

- 优点：

    - 加速收敛，减少震荡。

    - 在平坦区域更新更快。

- 缺点：可能冲过最优点。

---

3. **RMSProp**

- 原理：自适应调整学习率，对梯度较大的参数使用较小的学习率，反之亦然。

- 优点：

    - 解决 Adagrad 学习率单调衰减的问题。

    - 适合非平稳目标（如 RNN）。

- 缺点：超参数需调优。

> ✅ 适合处理稀疏梯度。
> 
> 

---

4. **Adam（Adaptive Moment Estimation）**

- 原理：结合 Momentum（一阶矩估计）和 RMSProp（二阶矩估计）。

- 优点：

    - 自适应学习率，收敛快。

    - 对大多数任务表现稳定。

    - 默认参数（如 β1=0\.9,β2=0\.999*β*1=0\.9,*β*2=0\.999）通常效果很好。

- 缺点：内存占用较高（需存储 m*m* 和 v*v*）。

> ✅ 目前最流行的优化器，广泛用于 CNN、Transformer 等。
> 
> 

---

5. **AdamW**

- 改进点：修正了 Adam 中 权重衰减（L2 正则） 的实现方式。

    - 原始 Adam 将权重衰减与梯度一起处理，效果不等价于 L2 正则。

    - AdamW 将权重衰减独立于梯度更新，更符合正则化本意。

- 优点：

    - 泛化性能更好。

    - 在训练大模型（如 BERT、ViT）时表现更优。



## 欠拟合\-Underfitting

欠拟合表示：模型在训练集和测试集上都表现不佳，无法捕捉数据的基本规律。

- 表现：

    - 训练误差高。

    - 测试误差也高。

- 原因：

    - 模型太简单（如用线性模型拟合非线性数据）。

    - 特征不足或特征工程不到位。

    - 训练不足（如迭代次数太少）。

- 解决方法：

    - 使用更复杂的模型（如增加网络层数、使用非线性模型）。

    - 增加有效特征。

    - 延长训练时间或调整学习率。

## 过拟合\-Overfitting

过拟合表示：模型在训练集上表现很好，但在测试集或新数据上表现差，过度记忆训练数据的细节和噪声，缺乏泛化能力。

- 表现：

    - 训练误差很低。

    - 测试误差明显高于训练误差。

- 原因：

    - 模型太复杂（参数过多）。

    - 训练数据太少或噪声多。

    - 训练时间过长。

- 解决方法：

    - 正则化：L1/L2 正则化（如 Ridge、Lasso）、Dropout（神经网络）。

    - 早停（Early Stopping）：在验证误差不再下降时停止训练。

    - 增加数据：数据增强、收集更多样本。

    - 简化模型：减少参数、剪枝（决策树）。

    - 集成方法：如随机森林、Bagging，降低方差。

## 怎么判断过拟合还是欠拟合

通过比较训练误差和验证/测试误差：

- 两者都高 → 欠拟合

- 训练误差低，验证误差高 → 过拟合

- 两者都低且接近 → 拟合良好



## 正则化方法

**正则化（Regularization）**是机器学习中用于**防止过拟合、提高模型泛化能力**的一类技术。其核心思想是通过在训练过程中引入额外的约束或惩罚，限制模型的复杂度。

常见方法有：

- **L1**** 正则化（Lasso）**

    - 原理：在损失函数中加入模型权重的 L1 范数（绝对值之和）：

    - 优点：具有特征选择能力，能将不重要特征的权重压缩为 0，实现稀疏化。

    - 缺点：在特征多于样本时可能不稳定。

    - 适用：高维数据、希望简化模型。

---

- **L2**** 正则化（Ridge）**

    - 原理：在损失函数中加入权重的 L2 范数（平方和）

    - 优点：

        - 使权重趋向于较小值，但不会为 0，提升模型稳定性。

        - 有效缓解过拟合。

    - 缺点：不进行特征选择。

    - 适用：大多数线性模型、神经网络（常称权重衰减）。

---

- **Dropout（神经网络专用）**

    - 原理：在训练过程中，随机“丢弃”一部分神经元（将其输出设为 0），比例由 `dropout rate` 控制（如 0\.5）。

    - 优点：

        - 打破神经元之间的共适应性，相当于集成多个子网络。

        - 显著提升神经网络的泛化能力。

    - 注意：测试时所有神经元都参与，输出需按比例缩放。

---

- **早停（Early Stopping）**

    - 原理：在训练过程中监控验证集误差。当验证误差不再下降甚至上升时，停止训练。

    - 优点：简单有效，避免模型在训练集上过度拟合。

    - 适用：所有迭代训练的模型（如神经网络、GBDT）。

---

- **数据增强（Data Augmentation）**

    - 原理：通过对训练数据进行随机变换（如图像的旋转、翻转、裁剪；文本的同义词替换）来增加数据多样性。

    - 优点：间接提高模型泛化能力，减少对特定样本的依赖。

    - 适用：图像、语音、文本等领域。

---

- **批量归一化（Batch Normalization）**

    - 原理：对每层的输入进行归一化（减均值、除标准差）。

    - 正则化效果：引入轻微噪声，具有一定的正则化作用，可减少对 Dropout 的依赖。

---

- **集成方法（Ensemble Methods）**

    - 如 Bagging（随机森林）、DropConnect 等，通过组合多个模型降低方差，提升稳定性。



## L1与L2正则化的区别

L1 和 L2 正则化都是用于防止模型过拟合的常用技术，它们通过在损失函数中添加惩罚项来限制模型复杂度，但在机制、效果和适用场景上有区别。

- L1将不重要的权重**压缩为 0**；L2 使所有**权重变小但不为 0**

- L1产生稀疏模型，可用于特征选择；L2 所有特征都保留

- L1对大权重的惩罚是线性增长； L2则是平方增长（更强）



# 五、Transformer

## Transformer组成

**（1）输入部分**

- **源文本嵌入层：**将源文本中的词汇数字表示转换为向量表示，捕捉词汇间的关系。

- **位置编码层：**为输入序列的每个位置生成位置向量，以便模型能够理解序列中的位置信息。

- **目标文本嵌入层（在解码器中使用）：**将目标文本中的词汇数字表示转换为向量表示。

**（2）编码器部分**

- 由N个编码器层堆叠（6层，每层8头）而成。

- **每个编码器层由两个子层连接结构组成：**第一个子层是多头自注意力子层，第二个子层是一个前馈全连接子层。每个子层后都接有一个规范化层和一个残差连接。

**（3）解码器部分**

- 由N个解码器层堆叠而成。

- **每个解码器层由三个子层连接结构组成：**第一个子层是一个带掩码的多头自注意力子层，第二个子层是一个多头注意力子层（编码器到解码器），第三个子层是一个前馈全连接层。每个子层后都接有一个归一化层和一个残差连接。

**（4）输出部分**

- **线性层：**将解码器输出的向量转换为最终的输出维度。

- **Softmax层：**将线性层的输出转换为概率分布，以便进行最终的预测。

## Transformer原理

首先，**输入**也就是源文本被映射为固定维度的词嵌入，与位置编码相加，以注入序列的位置信息。

**编码器**通过多头自注意力机制，使每个位置能够聚合整个输入序列的上下文信息：具体地说，就是将输入线性变换为查询（Q）、键（K）和值（V）矩阵，计算 Q 与 K 的点积并缩放，经 Softmax 得到注意力权重，再对 V 加权求和，输出上下文感知表示。随后，该表示通过前馈神经网络进行非线性变换。两个子模块都采用残差连接与层归一化，以稳定训练并缓解梯度问题。

**解码器**包含两个注意力子模块：第一个是，带掩码的多头自注意力机制通过对未来位置施加掩码，确保生成过程仅依赖已生成内容，维持自回归特性；再接着就是，编码器\-解码器注意力机制中，查询（Q）来自解码器，键（K）和值（V）来自编码器输出，使解码器在生成每个词时能动态聚焦于输入序列的相关部分。之后同样经过前馈网络及残差归一化处理。

最终，解码器的**输出**通过线性层映射到目标词表，并经 Softmax 输出概率分布，选择概率最高的词作为输出。

## 注意力机制

注意力机制 是一种让模型在处理序列时，能够 “`关注`” 输入中最重要部分的机制。 主要有如下：

1. **Soft Attention（软注意力）**

    - 对所有位置分配一个权重（Softmax），加权求和

    - 可微分，易于训练

    - 最常用形式

2. **Hard Attention（硬注意力）**

    - 只选择一个位置（如 argmax）

    - 不可微，训练困难

    - 少用

3. **Self\-Attention（自注意力）**

    - Q、K、V 来自同一输入序列

    - 每个词可以关注序列中其他词

    - 是 Transformer 的核心

4. **Multi\-Head Attention（多头注意力）**

    - 使用多组 Q、K、V 投影，学习不同子空间的注意力

    - 每个“头”关注不同的语义模式（如语法、语义、指代）



## 自注意力机制

**自注意力（Self\-Attention）** 是一种让序列中的每个元素“关注”序列中其他元素的机制，从而动态地捕捉全局依赖关系。



**自注意力就是让模型在处理每个词时，自动去找最相关的上下文信息。**



## 自注意力的计算步骤

给定一个输入序列（如词向量），自注意力通过以下步骤计算输出：

**步骤 1：生成 Q、K、V 向量 ；**每个输入向量 x 会通过三个线性变换，生成：

- Query（查询）：我在找什么？（关注哪些位置）

- Key（键）：我代表什么？

- Value（值）：我提供什么信息？

所有词都参与计算，形成 Q、K、V 矩阵

**步骤 2：计算注意力分数；**Query 和 Key 做点积，衡量“匹配度”：

**步骤 3：Softmax 归一化；**将分数转为概率分布（权重）

**步骤 4：加权求和 Value；**用权重对 Value 加权求和，得到每个位置的输出：

输出是一个上下文感知的新表示，融合了最相关的上下文信息

## 多头自注意力机制

**多头自注意力机制** 是让模型从多个不同的子空间角度，并行地学习输入序列中词与词之间的依赖关系，从而捕捉更丰富、更复杂的语义模式。



**多头自注意力的计算流程**

步骤 1：输入表示

步骤 2：线性投影（Split into Heads）为每个头分配一个子空间

步骤 3：并行计算自注意力；也就是每个头独立计算注意力

步骤 4：拼接多头输出（Concat）

步骤 5：线性变换（融合）通过一个线性层融合多头信息





## Transformer智能涌现的原因

“涌现”（Emergence）是指：当系统规模增大时，突然出现一些小模型不具备的新能力。

智能涌现 = Transformer 架构 × 大规模参数 × 海量数据 × 有效训练目标 × 规模临界点

1. 自注意力机制：全局依赖建模；每个词可以“看到”序列中所有其他词，支持长距离推理

2. 大规模参数：知识的“存储空间”；模型参数多，参数越多，知识密度越高，越容易“想起来”

3. 海量数据的训练；学习的东西多，更智能

4. 预训练 \+ 微调范式； 更专业



## Transformer与传统模型的区别

1. 并行处理能力：

    - Transformer：通过自注意力机制（self\-attention）允许模型并行处理整个序列，避免了序列数据处理的依赖关系，因此可以大大提高训练速度。

    - 传统模型（RNN/LSTM）：这些模型通常是顺序处理的，意味着每个步骤的计算依赖于前一个时间步，限制了并行处理的能力。

2. 自注意力机制：

    - Transformer：自注意力机制使得每个输入位置都能与序列中的所有其他位置进行交互，这样模型可以捕捉到序列中更远距离的依赖关系。比如，通过加权平均，模型可以动态调整输入之间的相关性。

    - 传统模型：RNN和LSTM依赖于通过递归的方式处理输入序列，虽然LSTM在理论上能捕捉长距离依赖，但在实践中仍然会遇到梯度消失或梯度爆炸的问题，尤其是处理很长的序列时。

3. 处理长序列的能力：

    - Transformer：由于自注意力机制，Transformer能够有效地处理非常长的序列，因为每个位置的表示都可以直接关注到其他位置的数据，不受递归计算的限制。

    - 传统模型：RNN和LSTM在处理长序列时容易丧失早期信息，特别是长时间的依赖关系，虽然LSTM比RNN更擅长处理长距离依赖，但仍然存在一定的局限性。

4. 训练效率和复杂度：

    - Transformer：由于其能够并行计算，因此Transformer的训练效率通常较高，尤其是在使用现代硬件（如GPU）时。其时间复杂度是O\(n^2\)，这是因为每个位置都要与所有其他位置计算注意力得分。

    - 传统模型：RNN和LSTM的时间复杂度是O\(n\)，因为每次仅需要计算一个时间步。然而，由于其顺序依赖，无法完全利用现代硬件的并行计算能力，训练速度通常较慢。

5. 应用场景：

    - Transformer：目前Transformer广泛应用于机器翻译、文本生成、图像生成等任务，并且大规模预训练模型（如BERT、GPT等）使其在自然语言处理（NLP）领域的表现非常出色。

    - 传统模型：RNN和LSTM在一些传统的时序数据任务中仍然有效，如语音识别、音频处理等，但在许多NLP任务中已被Transformer所取代。



## Transformer中的掩码机制

掩码机制主要有两种类型：自注意力掩码（Self\-Attention Masking）和序列掩码（Sequence Masking），具体如下：

1\. **自注意力掩码（Self\-Attention Masking）**

自注意力掩码主要用于控制模型在计算每个位置的表示时，能够“看到”哪些位置的输入。常见的掩码类型有两种：

**a\. 前向掩码（Causal Masking）**

- 用途：这种掩码主要用于生成模型（如GPT）中，确保在预测某个位置的输出时，模型只能看到当前位置之前的内容，而不能看到未来的信息。换句话说，每个位置只能依赖于之前的词语和当前词语，防止信息泄漏。

- 实现方式：通过设置一个上三角的矩阵，标记当前位置之后的元素为不可见（通常设为负无穷大）。这样，在计算注意力得分时，未来的元素就会被掩蔽掉，确保模型只能使用当前及之前的位置的信息。

**b\. 填充掩码（Padding Masking）**

- 用途：当处理的序列长度不一致时，通常需要对序列进行填充，以使得所有序列的长度相同。填充的位置不包含实际的信息，因此需要通过掩码机制来忽略这些填充符号。在计算注意力时，填充的位置不应对模型的学习产生影响。

- 实现方式：在填充的部分标记掩码为`0`，并在计算注意力时让模型忽略这些部分。

**2\. 序列掩码（Sequence Masking）**

序列掩码用于特定任务中，需要掩盖序列中某些位置的信息。常见的类型包括：

**a\. 随机掩码（Random Masking）**

- 用途：用于一些预训练任务，如BERT的掩码语言模型（Masked Language Model, MLM）。在这种任务中，输入序列中的一些位置会被随机掩蔽，模型需要预测被掩蔽的词汇。

- 实现方式：随机选择输入序列中的部分词汇，将其掩蔽（通常用特殊标记如`[MASK]`替换），然后训练模型去预测被掩蔽的词。

**b\. 固定掩码（Fixed Masking）**

- 用途：在某些情况下，掩码是预先确定的，特定位置的元素会被掩蔽。例如，在多任务学习中，可能会选择性地掩蔽一些输入位置来训练模型解决某个具体问题。

- 实现方式：直接指定掩蔽的输入位置。

## Transformer中的掩码类型

主要的掩码类型包括：

- 前向掩码（Causal Masking）：用于防止模型在生成任务中查看未来的信息。

- 填充掩码（Padding Masking）：用于忽略填充的无效位置。

- 随机掩码（Random Masking）：常用于预训练任务，如BERT中的MLM。

- 固定掩码（Fixed Masking）：用于特定的任务或训练设置。



## Transformer与BERT的区别

- Transformer：Transformer模型是一个深度学习架构，用于处理序列数据，主要由两个部分组成：编码器（Encoder）和解码器（Decoder）。每个部分都包含多头自注意力机制和前馈神经网络。

    - 编码器：负责从输入序列中提取信息。

    - 解码器：负责生成输出序列（如在翻译中从英语生成法语）。

- BERT：BERT仅使用Transformer的编码器部分，并且是一个双向的模型。这意味着BERT同时考虑了上下文的左右两边，而不像传统的Transformer模型那样只能单向地处理序列（从左到右或者从右到左）。



- Transformer是一个基础架构，适用于生成任务，包含编码器和解码器。

- BERT是基于Transformer的改进版，专注于理解任务，采用了双向编码器，并使用了预训练和微调的策略。

- Transformer：用于序列到序列任务，如机器翻译、文本生成、图像描述等。

- BERT：通常用于句子级别的理解任务，如情感分析、命名实体识别、问答系统、文本分类等。

## Transformer和CNN的区别

Transformer和CNN最根本的区别在于它们捕捉数据内在关系的方式。

- CNN 基于卷积核，通过局部连接和权重共享来提取特征。它有一个强的归纳偏置，即假设特征具有局部性和平移不变性。这使它效率高，特别适合图像类网格数据，但捕捉长程依赖需要深层的堆叠。

- Transformer 的核心是自注意力机制，它能直接计算序列中任意两个元素之间的关系，实现全局感知。它的归纳偏置很弱，更加数据驱动，因而在拥有海量数据时（如NLP、大语言模型）表现出色，但其计算复杂度随序列长度平方级增长是一个瓶颈。

简单来说，CNN是‘由局部到全局’，而Transformer是‘一眼看全貌’。

## Q、K、V的含义

在 Transformer 的 多头注意力机制（Multi\-Head Attention） 中：



## QKV计算

1. 输入表示（Token Embedding）：

    - 首先，输入序列被转换为一个词嵌入（Embedding），然后会加上位置编码（Positional Encoding）来表示序列中各个元素的位置信息。

2. 线性变换（Linear Transformation）：

    - 对输入的每个位置的表示（通常是一个向量），进行三个线性变换，分别得到Query（Q）、Key（K）和Value（V）。

    - 这些变换是通过训练得到的权重矩阵来完成的。

3. 计算注意力得分（Attention Scores）：

    - 通过Q和K的点积来计算注意力得分，衡量查询（Query）与键（Key）之间的相似度。

4. 应用掩码（Masking）：

    - 在Decoder\-Only架构中，为了保持自回归的性质（即当前时刻只依赖于之前的时刻），会应用掩码机制。具体来说，使用一个上三角的掩码矩阵，确保每个位置的表示只能关注到当前位置之前的信息，而不能访问未来的词。

    - 这样，生成的每个词只依赖于其前面的词，确保了自回归生成过程。

5. Softmax和加权求和：

    - 对注意力得分进行Softmax归一化，得到每个位置的权重。

    - 然后，利用这些权重对Value（V）进行加权求和，得到每个位置的最终输出

6. 多头注意力：

    - Transformer通常会使用多头注意力（Multi\-Head Attention）。这意味着将Q、K、V分别划分为多个子空间（头），每个头独立计算注意力得分，然后将多个头的输出拼接在一起，最后通过一个线性变换获得最终的输出



## Decoder\-Only架构中的QKV计算

1. 输入嵌入加位置编码。

2. 通过线性变换得到Query（Q）、Key（K）、Value（V）。

3. 计算Q和K的点积，得到注意力得分。

4. 进行缩放和应用掩码。

5. 对得分进行Softmax归一化。

6. 对Value（V）进行加权求和。

7. 多头注意力通过多个头并行计算得到最终的输出。





## 位置编码类型

1. **绝对位置编码** \(Absolute Positional Encoding\)

这类编码为序列中的每个位置分配一个唯一的向量，表示其在序列中的绝对位置。常见的有 正弦/余弦位置编码、可学习位置编码

2. **相对位置编码** \(Relative Positional Encoding\)

这类编码关注的是序列中两个元素之间的相对距离，而不是它们的绝对位置。这更符合许多语言任务的直觉（例如，注意力权重可能更依赖于两个词之间的距离）。

3. **旋转位置编码** \(Rotary Position Embedding, RoPE\)

将绝对位置信息编码为对查询（Query）和键（Key）向量进行旋转的操作。具体来说，每个位置对应一个旋转矩阵，通过旋转向量来注入位置信息。





## 旋转位置编码的优点

- 原理: 将绝对位置信息编码为对查询（Query）和键（Key）向量进行旋转的操作。具体来说，每个位置对应一个旋转矩阵，通过旋转向量来注入位置信息。

- 优点:

    - 具有良好的理论外推性，可以线性外推到更长的上下文。

    - 在长文本任务中表现优异。

- 应用: LLaMA、ChatGLM、Baichuan、Qwen 等许多现代大语言模型（LLM）都采用了 RoPE 或其变体。



## 多头注意力机制的必要性



多头注意力机制的必要性在于：它解决了单头注意力无法同时捕捉多样化语义关系的根本缺陷，通过“分而治之”的策略，让模型能够从多个互补的视角理解输入，从而极大地提升了模型的理解能力和性能。



## BERT模型

BERT（Bidirectional Encoder Representations from Transformers）是由Google在2018年提出的一种预训练语言表示模型。

1. **核心思想**

- 双向编码（Bidirectional）：与之前如Word2Vec、ELMo或GPT等模型不同，BERT通过同时考虑一个词的左右上下文来理解语义，从而获得更丰富的语言表示。

- 基于Transformer架构：BERT完全基于Transformer的Encoder部分，摒弃了RNN/CNN结构，利用自注意力机制（Self\-Attention）捕捉长距离依赖。

---

2. **模型架构**

BERT主要有两个版本：

- BERT\-Base：12层（Transformer blocks），768个隐藏单元，12个注意力头，参数量约1\.1亿。

- BERT\-Large：24层，1024个隐藏单元，16个注意力头，参数量约3\.4亿。

---

**为什么使用 BERT？**

1. **语义理解能力比较强**
BERT 通过 双向上下文建模 和 Transformer 架构，能够深入理解词语在具体语境中的含义。例如：

    - “苹果很好吃” vs “苹果发布了新手机”

    - BERT 能根据上下文区分“苹果”是水果还是公司。

2. 预训练 \+ 微调范式，**节省标注成本**
BERT 在大规模无标签语料（如维基百科、书籍）上进行了预训练，已经学到了丰富的语言知识。我们只需要在特定任务上进行少量数据微调（fine\-tuning），就能达到很好的效果，大大降低了对标注数据的依赖。

3. **通用性强，迁移能力好**
BERT 是一个通用的语言表示模型，可以迁移到多种 NLP 任务中，无需为每个任务从头设计特征工程或模型结构。

## Transformer哪部分最耗费算力资源

大多数大模型都是基于Transformer的解码器来实现的；所以您如果说是哪部分最耗费算力资源的话，应该是 解码器部分； 如果必须是Transformer（比如T5）；那么就是编码器和解码器，两部分都耗费。 

如果要硬说是哪部分，那么就是解码器（它有两个多头注意力机制，编码器只有一个）； 为什么？  因为多头注意力机制最耗费算力，原因： 每个头中的计算都是QKV多维矩阵的点积、缩放、非线性化等的计算，是非常耗费GPU资源的。

# 六、大模型基础

## 大模型中的 token

Token 是大语言模型处理文本的最小单位。

由于模型只能处理数字，不能直接理解自然语言，因此需要通过 分词器（Tokenizer） 将输入文本切分成一系列 token，并映射为对应的 ID 序列。

token 不等于单词。主流模型通常采用 子词分词算法（如 BPE、WordPiece），将词拆分为更小但高频的单元。例如，中文“人工智能”可能是一个或两个 token。



Token 的数量直接影响：

- 上下文长度限制（如 32K tokens），

- API 调用成本（按 token 计费），

- 推理速度和内存占用。



## MCP协议

**MCP**（Model Context Protocol ）叫作**模型上下文协议**，是一种标准化协议，它能够使大模型与**外部工具和资源进行交互**。

MCP 协议支持三种通信机制：基于标准输入输出**STDIO**的本地通信、基于[**SSE**](https://zhida.zhihu.com/search?content_id=254488153&content_type=Article&match_order=1&q=SSE&zhida_source=entity)（[Server\-Sent Events](https://link.zhihu.com/?target=https%3A//en.wikipedia.org/wiki/Server-sent_events)）和 `Streamable HTTP`（流式 HTTP）的远程通信方式。

- **本地通信：**通过** stdio** 传输数据，适用于在同一台机器上运行的客户端和服务器之间的通信。

- **远程通信：**利用 **SSE** 与 HTTP 结合，实现跨网络的实时数据传输，适用于需要访问远程资源或分布式部署的场景。Web 环境、需要单向流式推送（服务器 → 客户端）。

- **`Streamable HTTP`**（流式 HTTP）：双向流式通信；

    - 工作方式：

        - 客户端 POST 一个 MCP 请求到 HTTP 接口

        - 服务器不立即关闭连接，而是以 chunked transfer encoding 方式分块返回多个 JSON 消息

        - 每个 chunk 是一个完整的 MCP 消息（通常用 `\n\n` 分隔）

    - 优点：

        - 比 SSE 更灵活（支持请求体）

        - 比 WebSocket 更简单（基于 HTTP）

        - 适合大模型流式生成 \+ 工具调用混合场景

## 模型温度Temperature的原理

“温度”（Temperature）是大语言模型（LLM）生成文本时控制输出随机性的一个关键超参数。它源自统计物理和信息论中的“softmax”函数，用于调节概率分布的“尖锐”或“平滑”程度。

在语言模型中，每一步生成下一个词时，模型会输出一个 logits 向量（未归一化的**对数概率**），然后通过 softmax 函数将其转换为概率分布： $P(w_i)=\frac{e^{z_i/T}}{\sum_ie^{z_j/T}}$



- 当温度很低（比如接近 0）时，模型会对 下一个词的对数概率（原始得分）进行放大，使得最高分的词的概率趋近于 1，其他词的概率趋近于 0。这相当于让模型几乎总是选择当前最可能的词，因此输出非常确定、一致、保守，但可能显得重复或缺乏创意。

- 当温度很高（比如大于 1）时，下一个词的对数概率 被压缩，所有词的概率趋于接近，低分词也有较大机会被选中。这就引入了更多随机性，使得每次生成的结果可能不同，语言更多样、新颖，但也可能变得不连贯或不合逻辑。



## 模型压缩

模型压缩一种减小模型的规模、降低计算和内存开销，同时尽可能保持其原始性能的技术；包括有：模型剪枝、知识蒸馏 、量化、低秩分解、参数共享 。



- 剪枝、量化、低秩分解、参数共享：都是**对原始大模型本身进行修改或转换**，相当于给同一个模型“减肥”或“换装”。

- 知识蒸馏：是创造一个全新的、更小的学生模型，这个学生模型是**独立的**，只是它的“老师”是大模型。

## 模型剪枝

模型剪枝 \(Model Pruning\) 移除模型中“不重要”的连接、神经元或整个层，从而得到一个更稀疏、更小的模型。

- 权重剪枝 \(Weight Pruning\)：移除单个权重（通常将接近零的权重设为0）。

- 神经元/通道剪枝 \(Neuron/Channel Pruning\)：移除整个神经元或卷积层中的输出通道（filter），这能直接减少模型的宽度和计算量。

优点：可以显著减小模型大小。

缺点：可能需要重新训练（fine\-tuning）来恢复性能；非结构化剪枝的加速效果有限。

## 模型/知识 蒸馏

知识蒸馏 \(Knowledge Distillation, KD\) 训练一个更小、更简单的“学生模型”（Student Model）来模仿一个更大、更复杂的“教师模型”（Teacher Model）的行为，而不仅仅是学习原始数据标签。

优点：学生模型通常比原始模型小得多，但性能接近教师模型；是提升小模型性能的有效方法。

缺点：需要先有一个训练好的高性能教师模型。



## 模型量化

降低模型权重和激活值的数值精度，用更低比特的整数（如 INT8, INT4）代替高精度的浮点数（如 FP32, FP16）

- 后训练量化 \(Post\-Training Quantization, PTQ\)：在模型训练完成后进行量化，无需重新训练，速度快，但精度损失可能较大。

- 量化感知训练 \(Quantization\-Aware Training, QAT\)：在训练过程中模拟量化过程，让模型学习如何在低精度下工作，通常能获得更好的精度。

- 比特宽度：常见的有 FP16（半精度）、INT8（8位整数）、INT4（4位整数）等。INT4 甚至 2\-bit 量化是当前大模型压缩的热点。

优点：能显著减小模型体积（例如，FP32 到 INT8 可减少 75%），并大幅提升推理速度和能效。

缺点：低比特量化可能导致精度下降，需要仔细校准和调整。

## 大模型与Agent的区别

- 大模型 \(LLM\)：

    - 本质上是一个大规模参数化的神经网络模型，其架构通常基于 Transformer。

    - 它是一个被动的模式生成器，输入是文本序列（prompt），输出是基于概率分布的下一个 token 的预测。其行为完全由输入 prompt 和模型参数决定。

    - 在系统架构中，它通常作为一个服务（Service）或 API 被调用，例如通过 `text-generation` 接口提供文本续写能力。

- 智能体 \(Agent\)：

    - 是一个自主的软件实体（Autonomous Software Entity），遵循“感知\-思考\-行动”（Perceive\-Reason\-Act）的闭环架构。

    - 它是一个主动的决策系统，能够根据环境状态（如用户指令、外部反馈）自主规划并执行一系列动作以达成目标。

    - 在系统架构中，它是一个完整的应用层系统，LLM 只是其内部的一个组件。





## qwen2\.5\-7B模型

Qwen2\.5\-7B 采用与 GPT 系列相同的 仅解码器（Decoder\-only） 架构。这意味着它由堆叠的 Transformer 解码器层组成，通过自回归（Autoregressive）方式生成文本，即根据前面的 token 预测下一个 token。

- 总参数量：约 70亿 \(7B\)。

- 层数 \(Layers\)：32

- 隐藏层维度 \(Hidden Size\)：4096

- 注意力头数 \(Query Heads\)：32

- 键/值头数 \(KV Heads\)：8 （这是 GQA 的体现，32 个查询头共享 8 个键/值头）

- 中间层维度 \(FFN Intermediate Size\)：11008





## DeepSeek的架构

标准的 Decoder\-only Transformer 架构

DeepSeek\-V2 是一次架构上的重大升级，其最大特点是采用了 稀疏化的混合专家模型（Sparse Mixture\-of\-Experts, MoE）。

**MoE \(Mixture of Experts\) **

- 将模型中的前馈网络（FFN）层替换为多个“专家”（Experts）。

- 在每一次前向传播中，仅激活其中的一小部分专家（例如 2 out of 64），而非全部。

- 这使得模型可以拥有巨大的总参数量，但每次推理的计算量（FLOPs）却远低于同等规模的密集模型。



- 总参数量：236B（2360亿）

- 活跃参数量 \(Active Parameters per Token\)：\~21B（约210亿）

    - 这意味着虽然模型总很大，但每个 token 的计算成本只相当于一个 21B 的密集模型，极大地提升了推理效率。

- 专家数量 \(Number of Experts\)：64

- 每Token激活的专家数 \(Experts per Token\)：2

- 注意力头：

    - 使用 Grouped\-Query Attention \(GQA\)，进一步优化推理速度。

    - 查询头（Query Heads）和键/值头（KV Heads）分离，减少 KV Cache。

- 其他组件：

    - 位置编码：RoPE，支持 32K 长上下文。

    - 归一化：RMSNorm。

    - FFN 专家内部：同样采用 SwiGLU 结构。



## T5模型

T5（Text\-to\-Text Transfer Transformer）是由 Google Research 在 2019 年提出的一种革命性的统一式（Unified）预训练语言模型框架。它的核心思想是：将所有自然语言处理任务都统一建模为“文本到文本”（Text\-to\-Text）的转换问题。

T5 基于标准的 Encoder\-Decoder Transformer 架构。

- 编码器 \(Encoder\)：处理输入文本，生成上下文表示。

- 解码器 \(Decoder\)：基于编码器的表示，自回归地生成输出文本。

- 与 GPT 的区别：GPT 是 Decoder\-only，用于生成；T5 是完整的 Encoder\-Decoder，更适合需要理解输入并生成新文本的“转换”任务。

- 与 BERT 的区别：BERT 是 Encoder\-only，主要用于理解（如分类、NER），不擅长生成长文本。



## 多模态的实现原理

多模态（Multimodal）模型的核心目标是让 AI 能够像人类一样，同时理解并关联多种类型的信息，如文本、图像、音频、视频等。其实现原理的本质是：建立不同模态数据之间的对齐（Alignment）与融合（Fusion），并在统一的语义空间中进行联合建模。

## 对 LangGraph 的理解

LangGraph 是由 LangChain 团队开发的一个基于有向图（Directed Graphs）的编程框架，特别适合那些需要复杂、状态化、多步骤、循环或条件分支逻辑的应用。

LangChain 是构建 LLM 应用的“基础工具包”，而 LangGraph 是构建“复杂智能代理（Agent）工作流”的“高级编排引擎”。

LangGraph 的核心突破在于引入了有向图和持久状态（State）：

1. 有向图 \(Directed Graph\):

    - 将应用的逻辑流程建模为一个图，其中：

        - 节点 \(Nodes\): 代表具体的“动作”或“步骤”，例如：调用 LLM、执行工具、进行条件判断、处理数据等。

        - 边 \(Edges\): 代表节点之间的执行顺序和控制流。边可以是条件边 \(Conditional Edges\)，根据上一个节点的输出动态决定下一个要执行的节点，从而实现 `if-else`、循环等复杂逻辑。

    - 这种图结构天然支持非线性的、分支的、甚至循环的执行路径。

2. 持久状态 \(Persistent State\):

    - 这是 LangGraph 区别于简单函数调用链的关键。整个图的执行过程维护一个共享的、可变的状态对象 \(State\)。

    - 这个状态对象贯穿整个图的生命周期，所有节点都可以读取和更新这个状态。

    - 状态通常是一个字典或 Pydantic 模型，可以存储：用户输入、LLM 的回复、工具调用的结果、中间推理步骤、对话历史、循环计数器等。

    - 优点: 节点之间无需通过参数层层传递数据，而是通过共享状态进行通信，极大地简化了复杂流程的数据管理。

# 九、Agent工作流与平台

## Agent和大模型的区别

我的理解是，大模型和Agent是不同层级的概念。

大模型（如 GPT、Qwen、Llama）是基础的语言生成和理解引擎，而 Agent 是以大模型为核心、具备自主决策与行动能力的智能系统。

具体来说：

- 大模型本身是‘被动的’：它只能根据输入生成文本，无法主动调用工具、记忆历史或执行任务；

- Agent 是‘主动的’：它把大模型作为‘大脑’，但额外集成了 规划（Planning）、记忆（Memory）、工具使用（Tool Use）和反思（Reflection） 等能力，能自主分解任务、调用 API、迭代修正结果。

大模型是 Agent 的核心组件之一，但 Agent 是更完整的智能体架构。

## Agent工具调用

LLM 根据任务需求，自主决定调用哪个工具、传入什么参数，并解析工具返回结果以继续推理或作答。



## Agent记忆

1. 短期记忆：由LLM的上下文窗口维护，保证了当前任务内部的连贯性，但容量有限。

2. 长期记忆：通常由向量数据库实现，用于存储超越当前会话的重要信息。它通过语义相似度检索，让Agent能‘想起’相关的过往经历。

3. 外部记忆：指Agent通过工具调用实时获取的外部信息，如查询数据库或搜索网络。

一个高效的Agent，会在这三种记忆间无缝衔接：从长期记忆中回忆相关背景，在短期记忆中保持推理连贯，并利用外部记忆获取实时信息，最终做出明智的决策。其中，利用向量数据库的长期记忆系统，是解决Agent‘遗忘问题’的关键技术





## Agent挑战

1. 技术核心挑战：首先是可靠性问题，大模型的‘幻觉’会在多步推理中被放大。其次是规划与推理的脆弱性，面对复杂动态任务时容易失败。最后是工具调用的精确性和错误处理能力依然不足。

2. 系统工程挑战：高昂的延迟和成本使得许多实时应用难以落地，同时，评估Agent的绩效也变得异常复杂和昂贵。

# 十、数据构建

## 数据清洗具体哪些操作

1. 去除噪声：清理 HTML 标签、广告代码、特殊字符、乱码和多余空白。

2. 格式标准化：统一编码（UTF\-8）、大小写、日期/数字格式。

3. 去重：精确去重（哈希）和近似去重（MinHash\+LSH），避免数据偏差。

4. 语言识别与过滤：保留目标语言内容。

5. 长度过滤：剔除过短无意义或过长冗余的文本。



## 知识库数据怎么清洗

重点是提升检索准确性和上下文质量：

1. 文档切分：将长文档（如 PDF、网页）按语义合理分块（如按段落、标题），确保每块信息完整独立。

2. 元数据增强：添加来源 URL、标题、章节等元数据，便于后续过滤和溯源。

3. 关键信息保留：特别注意保留表格、代码块、术语定义等核心内容，避免切分破坏结构。

4. 低质量内容过滤：移除导航栏、页脚、版权声明等无关区域。

5. 向量化前处理：对文本块进行清洗后，再生成嵌入向量存入向量数据库。



## 微调数据怎么清洗

重点是保证样本质量和标注一致性：

1. 格式统一：确保所有样本符合预设格式（如 instruction\-tuning 的 `instruction`/`input`/`output` 结构）。

2. 标注质量审核：

    - 检查输入与输出的相关性，剔除答非所问的样本。

    - 评估输出的正确性、完整性和流畅性。

    - 对多轮对话，检查上下文连贯性。

3. 毒性与偏见过滤：严格移除包含歧视、偏见或有害内容的样本。

4. 数据平衡：检查不同类别、任务类型的样本分布，避免模型偏向。

5. 困惑度过滤：用小模型评估输出质量，过滤生成质量差的样本。

核心原则是：知识库清洗为“高效检索”服务，微调数据清洗为“高质量学习”服务。

## 文本切割的优化



1\. 根据文档类型选择策略

2\. 合理设置 chunk size 与 overlap

- 经验范围：256–1024 tokens（取决于 LLM 上下文和任务）。

- Overlap：通常设为 chunk size 的 10%\~20%（如 512 tokens → overlap 50–100）。

- 原则：确保一个完整句子/段落尽量落在同一个 chunk 内。

3\. 增强 chunk 的上下文信息

- 添加元数据：如来源文档名、章节标题、页码。

- 前缀/后缀注入：在 chunk 开头加入“本段来自《XXX》第3章”，增强上下文。

4\. 评估驱动优化

- 构建测试集，评估不同切分策略下的：

    - 检索召回率（Recall@K）

    - 答案准确率（Answer Accuracy）

    - 幻觉率（Hallucination Rate）

- 选择在业务指标上表现最优的方案。

5\. 动态切分（Dynamic Chunking）

- 根据内容密度动态调整 chunk 大小：

    - 技术性强、信息密集 → 切小；

    - 描述性、冗余多 → 切大。

## 语义分割文本

说了上一题的后还问；能不能按照语义分割文本的话； 那么回答：



我们也可以采用按照语义分割文本； 可以使用` nlp_bert_document-segmentation_chinese-base` 这个小型的bert模型；按照语义来分割文本。 



缺点：分割出来的文本块，大小不一；长度可能无法控制。



语义分割文本原理：

本质上是一个 “句子对分类” 或 “边界检测” 任务，基于 BERT 微调实现。它把“语义分段”转化为“相邻句子是否属于同一话题”的二分类问题，利用 BERT 强大的上下文语义理解能力，判断句子间的语义连贯性，从而在话题切换处精准切分。 

一般采用： 滑动窗口 \+ 边界二分类



步骤：

1. 将文档拆分为句子序列
使用中文分句工具（如 `pyltp`、`LAC` 或规则）得到句子列表：
`S = [s₁, s₂, s₃, ..., sₙ]`

2. 对每两个相邻句子 \(sᵢ, sᵢ₊₁\)，判断是否为“分割点”

    - 输入：`[CLS] sᵢ [SEP] sᵢ₊₁ [SEP]`

    > CLS 表示每个输入序列的开头标识符； SEP 表示同一个输入序列中的不同句子或文本片段。
    > 
    > 

    - 输出：二分类 —— “是否在此处切分”（0=不分割，1=分割）

3. BERT 编码 \+ 分类头

    - 用 BERT 获取 `[CLS]` 向量；

    - 接一个全连接层 \+ sigmoid，输出分割概率。

4. 后处理

    - 对所有相邻句对预测结果，取概率 \> 阈值的位置作为分割点；

    - 可加入最小段落长度约束等规则。

> BERT 能捕捉 上下文语义相关性（因为它是基于Transformer的编码器）。如果 sᵢ 和 sᵢ₊₁ 属于不同话题（如从“经济”跳到“体育”），它们的语义关联弱，模型就倾向于预测“分割”。
> 
> 



## 分块的评估

一个“好”的分块应该满足：

1. 语义完整：不切断句子、代码、逻辑；

2. 粒度合适：匹配下游任务需求；

3. 可检索：包含足够关键词/语义，能被 query 命中；

4. 信息充分：包含回答问题所需的最小上下文；

5. 结构友好：保留原始文档的层级/元信息。

最终验证标准：当用户提出一个问题时，最相关的 chunk 能独立支撑 LLM 生成准确、无幻觉的答案。

## 如何提高RAG系统的效果

提高RAG系统的整体效果，我会从检索、生成和系统架构三个层面进行系统性的优化。

1. 首先，核心是优化检索器，确保给LLM的资料是精准的。 我会：

    - 优化文本切分，使用语义切分保证块的信息完整性；大概会先从文本块大小、重叠数值、分割符调整。

    - 升级嵌入模型，选用像`BGE-M3`这样的模型，并在可能的情况下进行领域微调。

    - 采用混合检索 \+ 重排序 策略，先用向量和关键词检索广撒网，再用重排序模型精挑细选。

2. 其次，优化生成器，确保大模型能更好的检索到资料。 我会：

    - 设计强硬的系统提示词，命令大模型严格依据上下文作答，并对无法回答的问题明确提示拒绝回答。

    - 要求大模型引用来源，从而约束其行为，也方便追溯。

3. 最后，在架构层面，也可能会考虑更高级的模式。 比如：

    - 迭代检索，通过多轮问答逐步细化搜索，精准定位答案。

    - 智能路由，让系统能判断什么问题该走RAG，什么问题不该走，避免不必要的干扰。

总之，这是一个需要持续迭代的过程，我会使用像RAGAS这样的评估框架来量化每一步优化的效果。

## 大模型幻觉

**大模型幻觉（Large Model Hallucination）**指的是在使用大型语言模型（如GPT等）时，模型生成的内容并不真实或者不准确，即**模型会“编造”不真实的信息**。这种现象是因为大模型基于大量的文本数据训练，可能会生成听起来有逻辑但并不完全准确的内容，尤其是在缺乏明确训练数据或者无法理解背景的情况下。



**解决方法**：

1. 在应用的时候增加事实性约束 Prompt提示词

    - 明确指令：“请基于以下事实回答”

    - 加入约束：“不要编造，不知道就说‘我不清楚’”

    - 提供示例（few\-shot）：“像这样回答才是正确的”

2. 也可以 引入 RAG ；从知识库找相关事实（如数据库、文档）；将事实 \+ 问题 一起输入大模型；模型基于真实数据生成回答

## 准确率

总体预测中，不管是正例还是反例，预测对了多少；关注整体的预测正确性



## 精准率

在预测为正例的里面，有多少实际是正的；关注预测的准确性



## 召回率

在所有实际为正的样本中有多少被预测出来了；关注的是覆盖完整性



召回率衡量的是**模型在所有真实正例中，成功找出的比例**。公式是 TP / \(TP \+ FN\)。它关注的是‘有没有漏掉’，常用于信息检索、医疗诊断等不能容忍漏检的场景。

在 RAG 中，召回率更重要。因为如果相关文档没有被检索到，大模型就无法获取该知识，可能导致错误回答。而多召回几个无关文档，大模型通常可以忽略，影响较小。



## **优化召回率的核心参数与策略**

1. **top\_k（或 ****`k`****）**从向量数据库中检索前 k 个最相似的文档。

    - 影响：k 越大，召回率越高（但也可能引入噪声）。

    - 建议：

        - 初始值：`k=5~10`

        - 若召回不足 → 增大到 `k=20~50`，再配合重排（re\-ranker）过滤

2. **相似度阈值（score\_threshold）**；只返回相似度高于某阈值的结果。

    - 对召回率的影响：阈值越低，召回率越高（但精度下降）。

    - 适用场景：当向量相似度普遍偏低时，适当降低阈值可避免漏检。

    ```Java
    *# FAISS + LangChain*
    retriever = vectorstore.as_retriever(
        search_kwargs={"k": 10, "score_threshold": 0.3}  *# 默认可能 0.5*
    )
    ```

3. **调整检索算法与索引类型**；

    - 开启 exact search（暴力搜索）：100% 召回，但慢（仅用于小数据集调试）



4. **采用多路召回（Multi\-stage Retrieval）**

    - 同时用多种方式检索，合并结果：

        - 向量检索（dense）

        - 关键词检索（BM25 / sparse）

        - 规则匹配（如按标签、时间）

    - 显著提升召回率，尤其对长尾查询。

5. **调整分块策略**

    - 如果文档切分太粗 → 相关信息被截断 → 召回失败

    - 优化方向：

        - 减小分开大小 chunk size（如 512 → 256）

        - 使用 overlap（重叠切分）

        - 语义分块（按句子/段落边界）

> 分块不合理是 RAG 召回率低的最常见原因！
> 
> 



优化策略：

1. 先评估当前召回率：人工标注 100 个 query 的相关文档，看系统能召回多少。

2. 优先调 `top_k` 和分块策略：成本最低，效果最明显。

3. 再考虑混合检索 \+ 重排：平衡 Recall 和 Precision。





## TF\-IDF

词频（TF）：词在文档中出现的频率 $TF(t,d) = \frac{词 t 在文档 d 中出现的次数}{文档d的总次数} $



逆文档频率（IDF）：衡量词的普遍重要性   $IDF(t,D)=\log(\frac{语料库中文档总数}{包含词t的文档数})$



TF\-IDF = $TF(t,d)×IDF(t,D)$



## F1\-Score 分值

F1\-score 是精确率（Precision）和召回率（Recall）的调和平均数，用于衡量分类模型的性能，尤其适用于类别不平衡的数据集。

精确率（Precision）：预测为正类中真正为正的比例

精确率 = $\frac{TP}{TP+FP} $



召回率（Recall）：实际为正类中被正确预测的比例

召回率 = $\frac{TP}{TP+FN} $

> - TP：真阳性（True Positive）
> 
> - FP：假阳性（False Positive）
> 
> - FN：假阴性（False Negative）
> 
> 



- TF\-IDF 是“输入”：解决“如何表示文本”的问题；

- F1\-score 是“输出评估”：解决“模型表现好不好”的问题。

> - 正例：通常指我们重点关注、想要识别的那个类别。它就是“信号”。
> 
> - 负例：指我们不关注的、其他所有的类别。它就是“噪声”。
>

正例：垃圾邮件（因为我们重点关注它）。

负例：正常邮件（其他所有我们不关注的类别）。

## RAG有几种召回方式

常见的召回方式有以下几种，它们各有优势，通常组合使用：

1\. 向量召回 / 语义召回（Vector/Embedding Retrieval）

- 原理：将文档和用户查询都编码为高维向量（通过 `mxbai-embed-large`、`bge` 等嵌入模型），在向量空间中计算相似度（如余弦相似度），召回最相近的文档。

- 优势：能实现“语义匹配”，理解同义词和上下文，适合语义搜索。

- 劣势：可能忽略关键词匹配，对嵌入模型质量依赖高。

- 技术栈：FAISS, Milvus, Pinecone, Weaviate。

2\. 关键词召回 / 稀疏检索（Keyword/Sparse Retrieval）

- 原理：基于传统的信息检索技术，如 BM25 或 TF\-IDF，通过匹配查询和文档中的关键词进行召回。

- 优势：对精确的术语、实体、专有名词匹配效果好，可解释性强。

- 劣势：无法理解语义，遇到同义词或 paraphrase 时效果下降。

- 技术栈：Elasticsearch, Apache Solr。

3\. 图召回（Graph Retrieval）

- 原理：如果知识库构建了知识图谱（Knowledge Graph），可以通过图遍历（如邻居节点、路径查询）进行召回。

- 优势：能利用实体间的关系和结构信息，发现间接相关的内容。

- 适用场景：问答系统、推荐系统，需要推理实体关系的场景。

- 技术栈：Neo4j, JanusGraph。

4\. 混合召回（Hybrid Retrieval）

- 原理：将向量召回和关键词召回的结果进行融合排序（Fusion），如 Reciprocal Rank Fusion \(RRF\)、加权求和等。

- 优势：结合语义和关键词的优势，效果通常优于单一方法。

- 注意：这通常被视为一种“融合策略”，而非独立的召回路。

5\. 其他召回方式

- 规则召回：基于业务规则（如时间、热度、标签）进行召回。

- 协同过滤召回：在推荐场景中，基于用户行为相似性召回。

- 多模态召回：对于图文、音视频等多模态数据，使用对应的多模态嵌入模型进行召回。



在实际工程中，最常见的多路召回策略是 2 到 3 路。

最典型的配置：2 路召回

1. 一路：向量召回（语义召回）

2. 二路：关键词召回（BM25）

> 这是当前 RAG 系统的“黄金组合”。它能有效平衡语义理解与精确匹配，覆盖大多数场景，实现简单，效果稳定。
> 
> 

进阶配置：3 路召回

在 2 路基础上，根据业务需求增加：

- 第三路：图召回（如果存在知识图谱）

- 或 第三路：规则/热度召回（如召回最新文档、高评分文档）

## RAG中用户输入的问题特别长

1\. 查询重写（Query Rewriting）

- 原理：使用一个轻量级模型（如小模型或规则）**对原始长问题进行摘要、简化或重述**。

- 方法：

    - 摘要式重写：让模型生成原问题的简洁摘要作为检索查询。

        - *Prompt: “请用一句话概括以下问题的核心意图：\{\{long\_question\}\}”*

    - 关键词提取：提取问题中的关键实体、动词和主题词，拼接成短查询。

    - 意图识别 \+ 模板填充：先识别用户意图（如“对比”、“查找定义”），再用模板生成标准查询。

2\. 查询分解（Query Decomposition）

- 原理：**将一个复杂的长问题拆解为多个独立的子问题，分别进行检索，最后合并结果**。

- 适用场景：问题包含多个独立的疑问或需要多步推理。

- 示例：

    - 原问题：“请分析我提供的这份 50 页项目报告，总结其主要创新点、潜在风险，并对比去年的方案，最后给出改进建议。”

    - 分解为：

        1. “总结项目报告的主要创新点”

        2. “识别项目报告中的潜在风险”

        3. “对比今年项目报告与去年方案的差异”

- 优势：每个子查询更精准，检索效果更好。

- 挑战：需要设计合理的分解逻辑，可能引入额外延迟。

3\. 分层检索（Hierarchical Retrieval）

- 流程：

    1. 先对长文档（如用户上传的长报告）进行预处理，分割成段落或章节，并为其生成摘要或标题。

    2. 用长问题去检索这些摘要/标题，快速定位相关章节。

    3. 再在相关章节的细粒度内容中进行二次检索。

- 优势：大幅减少检索范围，提高效率和精度。

4\. 直接使用长上下文模型（Leverage Long\-Context LLMs）

- 前提：如果使用的嵌入模型和生成模型都支持超长上下文（如支持 128K 的 `gpt-4-turbo` 或 `Claude 3`）。

- 策略：

    - 可以直接将长问题与文档拼接，但需确保问题中最关键的信息位于上下文的开头或结尾（LLM 对中间位置的记忆较弱）。

    - 结合 Prompt Engineering，在问题末尾添加：“以上是背景信息，请重点关注最后的问题：\.\.\.” 来引导模型。

5\. 元数据过滤（Metadata Filtering）

- 原理：如果长问题中包含明确的过滤条件（如时间、作者、文档类型），可以先用这些条件在数据库层面进行硬过滤，缩小检索范围，再进行语义检索。

- *例：问题中提到“2023年发布的报告”，可先用时间元数据过滤。*

## 使用RAG技术的步骤

完整流程可分为 离线准备阶段 和 在线推理阶段 两大阶段

一、离线准备阶段（知识库构建）

步骤 1：数据收集与清洗

- 收集来源：企业文档、FAQ、PDF、网页、数据库、API 等。

- 清洗操作：

    - 去重（Deduplication）

    - 去噪（移除广告、页眉页脚）

    - 格式标准化（HTML/Markdown → 纯文本）

步骤 2：文本分块（Chunking）

- 将长文档切分为语义完整的短文本块（chunks）。

- 方法选择：

    - 固定长度 \+ 重叠（如 512 tokens，overlap=50）

    - 按段落/标题结构切分（推荐）

    - 高级策略：父子分块、语义聚类等

步骤 3：向量化与索引构建

- 使用 Embedding 模型（如 `bge-large-zh`, `text-embedding-3-large`）将每个 chunk 编码为向量。

- 构建索引：

    - 向量索引：存入向量数据库（如 Milvus, Pinecone, Qdrant, FAISS）

    - （可选）关键词索引：存入 Elasticsearch 等，用于混合检索

- 添加元数据：文档来源、时间、类型、章节标题等，便于过滤



二、在线推理阶段（用户问答）

步骤 4：查询理解与检索

- 用户输入问题（query）

- 检索：

    - 向量检索：将 query 编码为向量，在向量库中 ANN 搜索 top\-K chunks

    - （可选）关键词检索（BM25）→ 实现混合检索

    - （可选）元数据过滤：如限定时间范围、文档类型

- 结果融合与重排序（ReRank）：

    - 使用 RRF 或 Cross\-Encoder（如 `bge-reranker`）对候选 chunks 精排

    - 取 top\-3 \~ top\-5 最相关 chunks 作为上下文

步骤 5：上下文增强与生成

- 构造 Prompt

- 调用大语言模型（LLM）生成答案：

    - 可选模型：GPT\-4、Claude、Qwen、Llama 3、本地微调模型等

- （可选）后处理：

    - 添加引用来源（如“根据《XX文档》第3节…”）

    - 过滤敏感信息

步骤 6：评估与反馈闭环（持续优化）

- 自动评估：

    - 检索指标：Recall@K, MRR

    - 生成指标：Faithfulness（忠实度）、Answer Relevancy（相关性）

    - 工具：RAGAS、TruLens

- 人工评估：抽检回答质量

- 用户反馈：纠错入口

- 数据回流：将高质量问答对加入训练集，迭代优化 Embedding、Prompt 或 LLM



RAG 的完整步骤 = 离线建库（数据 → 分块 → 向量化） \+ 在线问答（检索 → 重排序 → 生成） \+ 持续优化



## RAG原理、流程

1. 检索（Retrieve）：

    - 当用户提出一个问题时，系统首先将其转化为一个“查询”（Query）。

    - 使用检索器（如向量数据库、Elasticsearch）在外部知识库（如文档库、维基百科、企业知识库）中搜索与查询最相关的文档片段（Passages）。

    - 常见技术：向量召回（Embedding \+ FAISS）、关键词召回（BM25）。

2. 增强（Augment）：

    - 将检索到的相关文档片段作为上下文（Context），与原始用户问题拼接在一起。

    - 形成一个新的、信息更丰富的 Prompt。

3. 生成（Generate）：

    - 将这个增强后的 Prompt 输入给大语言模型（LLM）。

    - LLM 基于检索到的上下文和自身语言能力，生成最终的答案。

## RAG有什么问题

1. 检索失败（Retrieval Failure）—— 最致命的问题

    - 语义鸿沟（Vocabulary Mismatch）：

        - 用户用“手机”提问，知识库用“移动设备”，关键词召回可能失败。

        - 嵌入模型未能将同义词映射到相近向量，语义召回失败。

    - 长尾查询：

        - 对于罕见或表述复杂的查询，可能检索不到任何相关文档。

    - 后果：LLM 在“无上下文”或“错误上下文”下生成，极易产生幻觉（Hallucination），回答看似合理实则错误。

2\. 噪声与干扰（Noise and Distraction）

- 检索到的文档可能包含大量与问题无关的冗余信息。

- LLM 可能被噪声干扰，提取错误信息，导致答案偏离主题。

3\. 多跳推理困难（Multi\-hop Reasoning）

- 有些问题需要结合多个文档的信息进行推理。

- RAG 通常只返回 top\-k 片段，LLM 难以在单次生成中完成复杂的逻辑整合。

4\. 上下文长度限制（Context Window Limitation）

- 检索到的文档、原始问题和生成答案都需要占用 LLM 的上下文窗口。

- 在长文档或多文档场景下，可能因截断而丢失关键信息。

5\. 延迟与成本（Latency and Cost）

- 额外延迟：检索步骤增加了系统响应时间（RT）。

- 计算成本：调用嵌入模型生成向量、查询向量数据库、运行 LLM，整个流程成本较高。

6\. 知识库质量依赖性强

- RAG 的效果高度依赖外部知识库的完整性、准确性和更新频率。垃圾进，垃圾出（Garbage in, garbage out）。

7\. 排序与融合问题

- 多路召回（如向量\+关键词）后，如何有效融合和重排序结果，直接影响最终效果。简单的融合策略可能效果不佳。

## RAG的评估指标

- BLEU：基于 N\-gram 精确度，常用于机器翻译。

- ROUGE：基于 N\-gram 召回率，常用于摘要任务，ROUGE\-L 较常用。

- METEOR：考虑同义词和词干的指标，比 BLEU/ROUGE 更接近人类判断。

- BERTScore：使用 BERT 模型计算 token 级别的相似度，当前更推荐，能捕捉语义等价。

## 生成的文本和参考答案之间的关系

评估方法主要分为两大类：自动化评估指标 和 人工评估。

1\. 基于 N\-gram 重叠的指标

- BLEU \(Bilingual Evaluation Understudy\)：

    - 原用于机器翻译，计算生成文本与参考答案之间 N\-gram 的精确度。

    - 局限：对同义词不敏感，分数与人类判断相关性一般。

- ROUGE \(Recall\-Oriented Understudy for Gisting Evaluation\)：

    - 常用于摘要任务，计算召回率（Recall），即参考答案中有多少 N\-gram 出现在生成文本中。

    - ROUGE\-L 基于最长公共子序列（LCS），对句子结构有一定容忍度。

    - 适用场景：评估生成答案是否覆盖了参考答案的关键信息。

> 注意：BLEU/ROUGE 在 RAG 中的适用性有限，因为 RAG 的答案可能用不同词汇表达相同意思。
> 
> 

2\. 基于嵌入的语义相似度指标

- 原理：将生成文本和参考答案编码为向量，计算它们之间的语义相似度。

- 常用方法：

    - Sentence\-BERT \(SBERT\)：使用预训练模型（如 `all-MiniLM-L6-v2`）获取句子向量，计算余弦相似度。

    - Google BLEU \(GLEU\) 或 BERTScore：

        - BERTScore 是当前更优的选择，它使用 BERT 模型计算生成文本和参考答案中每个 token 的相似度，再通过 Precision、Recall 和 F1 值进行评估。

        - 它能捕捉语义等价性，比传统 BLEU 更接近人类判断。

3\. 基于大模型的评估（LLM as a Judge）

- 原理：使用一个更强大、更可靠的 LLM（如 GPT\-4、Claude 3）作为“裁判”，输入生成答案、参考答案和问题，让其打分或判断优劣。

- 评估维度：

    - 事实一致性（Factuality）：生成答案是否与参考答案（或检索到的上下文）事实一致。

    - 相关性（Relevance）：是否回答了问题。

    - 完整性（Completeness）：是否覆盖了所有要点。

    - 流畅性（Fluency）：语言是否自然。

- 优势：评估质量高，接近人类水平。

- 劣势：成本高、速度慢、可能存在裁判模型的偏见。

4\. RAG 特有的评估指标

这些指标直接关联 RAG 的核心流程：

- 检索相关性（Retrieval Relevance）：

    - `Hit Rate@K`：检索到的 top\-K 文档中是否包含与问题相关的文档。

    - `MRR (Mean Reciprocal Rank)`：衡量第一个相关文档的排名。

- 答案忠实度（Answer Faithfulness）：

    - 评估生成的答案是否忠实于检索到的上下文，有没有捏造（幻觉）信息。

    - 可通过 NLI（自然语言推理）模型判断答案是否能从上下文中“蕴含”（Entailment）。

- 上下文相关性（Context Relevance）：

    - 检索到的文档是否真的有助于回答问题。



## RAG有图片和视频该怎样处理

当 RAG 系统需要处理图片、视频等非文本模态数据时，传统的纯文本 RAG 架构就不再适用。我们需要构建一个 多模态 RAG（Multi\-modal RAG） 系统。

多模态 RAG 的工作流程在传统 RAG 的基础上增加了多模态编码与理解环节：

1. 多模态数据预处理：

    - 对图片、视频帧、音频等进行提取和标准化。

2. 多模态内容提取与编码：

    - 使用多模态模型将非文本信息转化为文本描述或多模态向量。

3. 索引构建：

    - 将提取的文本和向量存入支持多模态检索的数据库。

4. 多模态检索：

    - 根据用户查询（文本或图像），检索最相关的多模态内容。

5. 多模态上下文增强与生成：

    - 将检索到的图像、视频片段及其文本描述提供给多模态大模型（如 GPT\-4V, Gemini, Qwen\-VL），生成最终答案。





## 知识库数据爆炸性增长要如何解决

1. 分层存储（Tiered Storage）根据数据的访问频率、时效性和重要性，将数据存放在不同成本和性能的存储层。

2. 采用分布式向量数据库（如 Milvus, Elasticsearch Cluster）实现水平扩展

3. 数据预处理与清洗

    - 去重（Deduplication）：

        - 在入库前识别并删除重复或高度相似的文档（使用 MinHash、SimHash 等算法）。

    - 信息提取与摘要：

        - 对长文档进行关键信息提取或生成摘要，用更小的“元数据”代替原始全文进行索引和检索。

        - 原始内容可存于冷存储，按需加载。

4. 智能索引策略

    - 混合索引（Hybrid Indexing）：

        - 结合 倒排索引（关键词） 和 向量索引（语义），提高检索效率和准确性。

    - 分块策略优化（Chunking）：

        - 不再简单按固定长度切分，而是按语义边界（如段落、章节）切分。

        - 使用 滑动窗口（Sliding Window） 或 父子分块（Parent\-Child Chunking） 提高上下文完整性。

    - 元数据过滤（Metadata Filtering）：

        - 为文档添加丰富的元数据（时间、来源、类型、标签），在检索时先用元数据快速缩小范围，再进行语义搜索。

5. 数据生命周期管理（Data Lifecycle Management）

    - 自动归档：设置策略，将超过一定时间（如 6 个月）且无访问记录的数据自动迁移到冷存储。

    - 数据过期与删除：对于有明确时效性的数据（如新闻、公告），设置 TTL（Time\-To\-Live）自动清理。

    - 定期审计：评估数据价值，对长期无用的数据进行归档或删除。





## 怎么处理回答错了

优先通过自动化手段（如忠实度检查、用户反馈）来识别和缓解错误；对医疗、金融等高风险领域的问题，启用“人工审核队列（人工干预）”，答案生成后由专家确认再返回。



## RAG的检索效率怎么提升

1\. 优化向量编码（Embedding Efficiency）

- 问题：嵌入模型推理是主要延迟来源之一。

- 解决方案：

    - 选用轻量化 Embedding 模型：如 `bge-m3`, `jina-embeddings-v2-small`, `text2vec` 等，在效果和速度间取得平衡。

    - 模型蒸馏（Distillation）：用大模型（如 BGE\-large）作为教师模型，训练一个更小、更快的学生模型。

    - 缓存查询向量（Query Caching）：

        - 对高频查询或相似查询的结果进行缓存（如 Redis），避免重复编码。

        - 使用 MinHash 或 SimHash 快速判断查询相似性。

2\. 加速向量检索（ANN Optimization）

- 问题：海量向量下的近似最近邻搜索仍可能较慢。

- 解决方案：

    - 选择高效的 ANN 算法：

        - HNSW \(Hierarchical Navigable Small World\)：速度快，召回率高，内存占用大。

        - IVF \(Inverted File Index\)：内存友好，可通过 `nprobe` 参数调节速度/精度。

    - 参数调优：

        - 调整 `ef_search` \(HNSW\), `nprobe` \(IVF\) 等参数，在召回率（Recall） 和 查询延迟（Latency） 之间找到最佳平衡。

    - 量化（Quantization）：

        - 使用 PQ \(Product Quantization\) 或 SQ \(Scalar Quantization\) 将浮点向量压缩为低位表示，大幅减少内存占用和 I/O，加速计算。

3\. 智能索引与数据预处理

- 问题：检索范围过大，噪声多。

- 解决方案：

    - 元数据过滤（Metadata Filtering）：

        - 先用业务规则（如时间范围、文档类型、标签）过滤，缩小向量搜索范围。

        - *例：问题“2024年的财报” → 先过滤 **`year=2024`** 且 **`type=report`** 的文档。*

    - 分层索引（Tiered Indexing）：

        - 将知识库按热度/时效性分层（热/温/冷），优先在热数据层检索。

    - 摘要索引（Summary Indexing）：

        - 对长文档生成摘要，先用摘要进行粗筛，再对候选文档的细粒度块进行精搜。

4\. 查询优化（Query Optimization）

- 问题：原始查询质量差，导致检索效率低。

- 解决方案：

    - 查询重写（Query Rewriting）：

        - 用小模型将冗长、模糊的查询简化为简洁、精准的关键词或短语，减少编码和搜索开销。

    - 查询分解（Query Decomposition）：

        - 将复杂问题拆解为多个简单子查询，并行检索，提高准确性和可管理性。

5\. 混合检索与结果融合优化

- 问题：多路召回（向量\+关键词）融合过程耗时。

- 解决方案：

    - 异步并行召回：向量检索和关键词检索并行执行，取两者结果的并集。

    - 高效融合算法：

        - 使用 RRF \(Reciprocal Rank Fusion\)，计算简单，无需统一分数尺度。

        - 避免复杂的 Learning\-to\-Rank 模型，除非必要。

    - 控制召回数量：合理设置每路召回的 top\-k 数量，避免后续处理压力过大。

6\. 架构与基础设施优化

- 分布式与水平扩展：

    - 使用分布式向量数据库（如 Milvus Cluster, Pinecone）实现横向扩展。

- 缓存机制：

    - 结果缓存：对高频问答对的结果进行缓存。

    - 向量缓存：缓存常用文本的嵌入向量。

- 硬件加速：

    - 在支持的环境下，使用 GPU 加速向量计算和 ANN 搜索。



## ReRANK的目的

在初筛召回的候选文档中，进一步提升相关文档的排序质量，从而为后续的生成阶段提供更精准、更相关的上下文信息。

RAG 的检索通常分为两个阶段：

1. 第一阶段：粗召回（Candidate Retrieval）

    - 使用 高效但精度有限 的方法（如向量 ANN 搜索、BM25）从海量知识库中快速召回 top\-K（如 100\~1000）个候选文档。

    - 目标是高召回率（Recall），确保相关文档不被漏掉，但排序可能不准。

2. 第二阶段：**精排序（ReRanking）**

    - 对粗召回的少量候选文档，使用 更精准但计算昂贵 的模型进行重新打分和排序。

    - 目标是高排序精度，把最相关的文档排到最前面。



- 典型流程：
`用户问题 → 向量/BM25 召回 top-100 → Cross-Encoder ReRank → 取 top-5 → 送入 LLM 生成`

## ReRank的方法

1. Cross\-Encoder 模型（最常用）

    - 如 `bge-reranker`, `Cohere rerank`, `SBERT Cross-Encoder`。

    - 将 查询和文档拼接 输入 Transformer，输出相关性分数。

    - 优势：能建模查询与文档的深度交互，精度远高于双塔模型（如普通 Embedding）。

    - 劣势：计算开销大，只能用于小规模候选集（通常 \< 100）。

2. Learning\-to\-Rank \(LTR\)

    - 基于多个特征（BM25 分数、向量相似度、点击率等）训练排序模型。

3. LLM\-based ReRanking

    - 用大语言模型判断相关性（成本高，一般用于评估或关键场景）。





## 混合索引怎么做的

**双路独立索引 \+ 后期融合（最常用）**

具体步骤如下：

1. 数据预处理
原始文档 → 切分成 chunks（文本块）。

2. 构建两个独立索引：

    - 向量索引：用 Embedding 模型（如 `bge-large`）将每个 chunk 编码为向量，存入向量数据库（如 Milvus, Pinecone, Qdrant）。

    - 关键词索引：将 chunk 的原始文本存入全文搜索引擎（如 Elasticsearch, OpenSearch），建立倒排索引。

3. 查询时并行检索：

    - 用户输入 query；

    - 同时发送给：

        - 向量数据库 → 返回 top\-K 语义相关 chunks；

        - Elasticsearch → 返回 top\-K 关键词相关 chunks。

4. 结果融合（Re\-Ranking / Fusion）；将两路结果合并，重新排序



## 为什么用稀疏和稠密向量

同时使用稀疏向量（Sparse Vectors）和稠密向量（Dense Vectors），是为了融合关键词匹配的精确性与语义理解的泛化能力，从而构建一个更鲁棒、更全面的检索系统。

> - 稀疏 = “查字典”：看 query 和文档是否包含相同关键词；
> 
> - 稠密 = “懂意思”：看 query 和文档是否表达相似含义。
> 
> 

稀疏向量：擅长精确匹配；对专有名词、ID、代码、数字、术语极其敏感，可解释性强：能明确知道是哪个词匹配上的。

稠密向量：擅长语义泛化；理解同义词、 paraphrasing、上下文语义，支持“问法不同，答案相同”的场景。

> 例子：
> 
> 用户问：“手机充不进电怎么办？”
> 
> - 稠密检索 → 找到“移动设备无法充电的故障排查指南” \-\-\-\>语义上理解（相似度检索）
> 
> - 稀疏检索 → 找到包含“充不进电”、“充电口损坏”等关键词的 FAQ  \-\-\-\> 倒排索引检索
> 
> 
> → 混合后，既覆盖专业文档，又命中用户原话，答案更全面。
> 
> 



## 什么是BM25算法

用于衡量一个查询（query）与一个文档（document）之间的相关性得分。

BM25 通过以下两个关键指标来计算相关性：

1. 词频（Term Frequency, TF）：
如果一个词在文档中出现得越多，该文档越可能与查询相关。

2. 逆文档频率（Inverse Document Frequency, IDF）：表示词在所有文档中出现的频率，越高越不重要，分值就越低（物以稀为贵）
如果一个词在语料库中非常常见（如 “the”, “是”），它的区分度就低；反之，罕见词（如 “量子纠缠”）更有信息量。

也就是可以理解为：一般来说 TF  和 IDF 越高，相关性得分就越高，也就是BM25的值越大，与对应的文档也就越相关。

## BM25检索流程

步骤 1：我们会对mysql中存储的高频问题构建倒排索引（Offline）

- 对所有文档进行分词；

- 建立“词 → 文档列表”的倒排索引；

- 同时记录每个词在每篇文档中的 TF、文档长度等元信息；

- 计算每个词的 IDF（基于整个语料库）。

步骤 2：在用户搜索的时候，对用户问题进行分词，到构建的倒排索引库中检索

- 对用户查询进行分词（通常小写、去停用词）；

- 对查询中的每个词，从倒排索引中找出包含该词的候选文档。

步骤 3：计算 BM25 得分并排序

- 对每个候选文档，按bm25公式计算总分；

- 按得分从高到低排序，返回 top\-K 结果。

步骤4：找到top\-k的问题，查这问题对应的答案并返回



## BM25 和 TF\-IDF 

BM25 和 TF\-IDF ——这两个是信息检索（Information Retrieval, IR）领域最经典的稀疏向量检索模型，常用于搜索引擎、文档匹配、RAG（检索增强生成）等场景。

TF\-IDF 和 BM25 都是用来衡量：**一个词在一篇文档中的重要程度**。

进而用于：

- 文档排序（搜索引擎）

- 相关性打分

- 关键词提取

- 作为向量空间模型的基础

![image\.png](图片和附件/image.png)

BM25 是 TF\-IDF 的升级版。它解决了 TF\-IDF 的两个主要问题：

1. 文档长度偏差：长文档天然 TF 更高

2. TF 增长饱和问题：一个词出现 100 次并不比 10 次重要 10 倍



# 十二、大模型微调

## 大模型微调方法

一、全量微调：在预训练好的模型基础上，使用新的领域或任务数据，对所有模型参数进行更新。成本高

二、参数高效微调：只更新模型的一小部分参数，从而极大地降低了计算和存储成本。

- **Adapter适配器**

    - 核心思想：在Transformer的每个层中插入小型的前馈神经网络模块。在微调时，冻结原始模型的所有参数，只训练这些新插入的适配器。

    - 工作方式：适配器通常放在自注意力层和前馈网络之后，形成一个残差连接。

    - 优点：参数效率高，避免了灾难性遗忘。

    - 缺点：会引入额外的推理延迟，因为增加了模型深度。

- **提示微调 / P\-Tuning**

    - 核心思想：不修改模型本身，而是在输入中引入一些可训练的“软提示”向量，与输入文本的嵌入向量一起送入模型。通过训练这些提示向量来引导模型产生期望的输出。

        - P\-Tuning v1：主要针对NLU任务，在输入层引入可训练的提示向量。

        - P\-Tuning v2：将可训练提示向量扩展到每一层Transformer，效果显著提升，成为目前的主流方法。

    - 优点：不改变模型架构，几乎没有推理延迟；参数效率极高。

    - 缺点：通常需要比适配器或LoRA更多的训练步数才能收敛。

- **LoRA及其变种微调**

    - 核心思想：假设模型在适应新任务时，权重变化具有“低秩”特性。因此，它不直接更新原始权重矩阵 W，而是用两个小的矩阵 A 和 B 的乘积来模拟其更新量：W′=W\+BA。在训练时，只训练 A 和 B。

    - 优点：

        - 极高的参数效率和无推理延迟（训练结束后，可以将 BA 合并回原权重 W）。

        - 性能通常能与全量微调相媲美。

        - 非常灵活，可以只针对某些层的注意力机制进行微调。

    - 流行变种：

        - QLoRA：将模型以4位精度量化，然后再应用LoRA。

        - AdaLoRA：动态地分配参数预算给最重要的权重矩阵，进一步提升参数效率。



## LoRA微调原理

LoRA（Low\-Rank Adaptation）是一种高效微调大模型的方法：它不修改原始模型的权重，而是在训练时“冻结”大模型，只添加少量可训练的低秩矩阵来模拟参数变化，从而大幅减少计算和存储成本。



核心原理：
大模型在适应新任务时，权重的更新方向其实存在于一个低维子空间中。不直接更新原始权重矩阵 W，而是用两个小的矩阵 A 和 B 的乘积来模拟其更新量；

$W' =  W + \Delta W = W + A \cdot B$

- 训练时冻结 *W*，只更新 *A* 和 *B*；

- 推理时可以把 *A*⋅*B* 合并回 *W*，零延迟。

## LoRA和adapter微调区别

Adapter 在网络中插入额外模块，会增加推理延迟；LoRA 修改权重本身，可合并，无延迟。





## 什么时候会选择微调大模型

选择微调大模型的核心场景有以下几种：

1. 任务专属化：当通用模型无法满足特定任务的高精度要求时（如法律审阅、医疗诊断），需微调以获得“专家级”能力。

2. 知识私有化：当业务依赖私有数据或最新知识（如公司内部文档、数据库），且不愿通过RAG在提示中暴露时，通过微调将知识内化到模型中。

3. 风格对齐化：当需要模型输出符合特定的风格、语气或格式（如品牌口吻、固定JSON结构）时，微调能实现稳定、统一的输出。

4. 成本与延迟优化：对于高频使用的特定任务，一个微调后的小模型比持续调用巨型通用API更经济、快速且可控。

反之，如果需求能通过提示工程或RAG解决，则应优先选择这些更轻量、低成本的方式。 微调是解决模型“能力”或“知识”根本性不足的手段。





## 微调时的超参数都有哪些

在微调大模型时，我主要关注以下几个核心超参数：

1. 学习率：这是最关键的一个。我会使用一个较小的值（比如1e\-5），并配合Warmup和线性衰减策略，目的是在适应新任务和保留预训练知识之间取得平衡。

2. 训练轮数：我会根据验证集的性能采用早停法来动态确定，防止模型过拟合到训练数据上。

3. 批量大小：主要根据GPU显存设置为所能承受的最大值，以保证训练效率。

4. 权重衰减：通常会设置一个较小的值（如0\.01）来作为正则化，提升模型的泛化能力。

至于优化器内部参数，我一般会沿用其默认值，因为它们对大模型已经很友好了。





## 微调数据的构建方法

构建微调数据的核心在于质量优先，大概可以：

1. 定义结构：根据微调目标（指令遵循、对话等）确定数据格式，如 `(指令，输入，输出)`。

2. 生成数据：优先采用 ‘大模型生成 \+ 人工精校’ 的高效混合模式。先生成大量候选数据，再由经过培训的标注员对关键样本进行审核和修正。

3. 严格清洗：进行去重、格式标准化和内容过滤。

4. 质量校验：这是最关键的一步。必须通过人工审核或模型交叉验证来保证数据的正确性和多样性，确保我们喂给模型的是高质量的数据。

最终，数据会被规范化为像 JSONL 这样的标准格式，用于训练。



## 微调中的过拟合问题

在微调中，过拟合通常是因为模型在有限的数据上训练过度，比如数据量太少、训练轮次太多或学习率太大，导致模型记住了训练集的噪声而非学会泛化规律。

我的解决方案会从三个层面入手：

1. 数据优先：首先考虑增加高质量数据或进行数据增强，这是最根本的。

2. 训练控制：我一定会使用早停法，并设置一个较小的学习率，这是微调时的标准做法。

3. 方法选择：我会优先采用像 LoRA 这样的参数高效微调方法。它本身通过限制可训练参数量，就是一种非常强大的正则化手段，能有效防止过拟合。

总结来说，就是通过 ‘更多更好的数据’、‘更谨慎的训练策略’和‘更高效的微调方法’ 三位一体来共同解决过拟合问题。

## 微调中的学习率设置

通用范围：通常设置一个较小的学习率，范围在 `1e-5`（0\.00001）到 `1e-4`（0\.0001） 之间。

为什么这么小？

- 避免灾难性遗忘：大学习率会猛烈更新权重，破坏模型在预训练阶段学到的宝贵通用知识。

- 稳定收敛：小学习率使训练过程更稳定、可控，允许模型平滑地适应新数据分布。

在使用过程中不会固定学习率；会使用调度器，进行学习率 `Warmup`（预热） 后接 `Linear Decay`（线性衰减）。预热保证训练初期的稳定性，衰减则利于后期精细收敛。



## 微调中的batch size选择

Batch Size 的选择本质上是 训练梯度稳定性、硬件利用率和模型泛化能力 之间的权衡。

在 GPU 显存不溢出的前提下，尽可能使用较大的 Batch Size（比如32或64），这能最大化硬件利用率，加快训练速度。

- 大Batch 训练稳定且高效，但可能导致模型泛化能力稍差。

- 小Batch 训练虽慢且震荡，但噪声可能起到正则化作用，有助于找到更鲁棒的解决方案。

如果我的首要目标是最终模型的泛化性能，我会倾向于选择较小的Batch Size。在实际操作中，我会固定其他参数，尝试不同的Batch Size，并根据验证集上的性能来做出最终选择。

## 微调中Epoch怎么设置

Epoch 是什么：整个训练数据集被模型完整学习一遍的次数。

- 太少的 Epoch（欠拟合）：模型还没有充分学习数据中的规律，性能未达到最优。

- 太多的 Epoch（过拟合）：模型开始“死记硬背”训练数据，包括其中的噪声和特定模式，导致在未见过的数据（验证集/测试集） 上性能下降。这是微调中最主要的风险。

由于预训练模型已经具备了强大的基础能力，微调只是“点拨”和“适应”，因此所需的 Epoch 通常不多。范围可能在 3 到 10 个之间，对于大型模型或小数据集，甚至更少。

## epoch与batch

每个epoch是一轮训练，每个epoch下有多个batch；1个epoch就是将所有训练数据训练完的意思；而1个batch就是这个epoch下每次训练几条数据。 例如；训练数据100条， 1个epoch就是完整训练100条数据的意思，而batch为10的话，那么就是每个epoch，要分 100 / 10 = 10 次；要分10次才能训练完。



## 微调中的早停策略/早停法

早停法是一种正则化技术，用于在模型开始过拟合训练数据时自动停止训练，从而找到泛化能力最强的模型状态。

**工作原理**

1. 数据划分：将数据分为训练集（用于更新模型参数）和验证集（用于评估模型泛化性能，不参与训练）。

2. 监控验证集指标：在每一个Epoch（或一定步数）训练结束后，在验证集上计算评估指标（如 准确率、F1分数 或 损失值）。

3. 提前终止条件：当验证集性能在连续多个Epoch（由 `patience` 参数控制）内不再提升 或 开始下降 时，触发停止。

我的做法：

早停法是我在微调中防止过拟合的核心策略。它的实现非常简单有效：

1. 我会准备一个独立的验证集，并在训练中持续监控其上的性能（如验证损失）。

2. 我设置一个 `patience` 参数（比如3）。这意味着如果验证集性能连续3个Epoch都没有提升，我就认为模型已经过拟合，并立即停止训练。

3. 最关键的一点是，我会开启 `restore_best_weights` 选项。这样，训练停止后，模型会自动恢复到它在验证集上表现最好的那个检查点的状态。

## 微调中的评估指标

1. 分类任务：我首选 F1分数，因为它能综合平衡精确率和召回率，尤其在类别不平衡的数据集上比准确率更可靠。

2. 生成任务：

    - 对于摘要，我使用 ROUGE 指标。

    - 对于翻译，我使用 BLEU 指标。

    - 不过这些自动指标有局限性。对于像对话这样的开放式生成任务，人工评估其流畅度和有用性是必不可少的最终环节。

## 线性回归原理

线性回归是一种基础的监督学习算法，其核心原理是：

假设目标变量（因变量）与一个或多个特征（自变量）之间存在线性关系。模型通过拟合一条直线（一维）或超平面（多维），使得预测值与真实值之间的误差最小。

数学表达式为：

y=w1x1\+w2x2\+\.\.\.\+wnxn\+b*y*=*w*1*x*1\+*w*2*x*2\+\.\.\.\+*wnxn*\+*b*

其中 *y* 是预测值，*xi* 是特征 *wi* 是权重（参数），*b* 是偏置。

## 线性回归与逻辑回归的区别

线性回归和逻辑回归主要有以下几点区别：

1. 任务类型不同：

    - 线性回归：用于回归任务，预测连续的数值型输出，比如预测房价、温度。

    - 逻辑回归：用于分类任务，预测离散的类别标签，比如判断邮件是否为垃圾邮件（是/否）。

2. 输出形式不同：

    - 线性回归直接输出一个连续值。

    - 逻辑回归先计算线性组合，然后通过 Sigmoid 函数 将结果映射到 \(0, 1\) 区间，输出一个概率值，表示属于某一类的可能性。

3. 核心函数不同：

    - 线性回归使用线性函数：y=wx\+b*y*=*wx*\+*b*。

    - 逻辑回归在内部使用线性函数，但最终输出是：P\(y=1\)=11\+e−\(wx\+b\)*P*\(*y*=1\)=1\+*e*−\(*wx*\+*b*\)1。

4. 损失函数不同：

    - 线性回归通常使用均方误差（MSE）作为损失函数。

    - 逻辑回归使用对数损失（Log Loss）或交叉熵损失，更适合处理概率输出和分类问题。

## 朴素贝叶斯分类器

朴素贝叶斯分类器是一种基于贝叶斯定理的简单概率分类算法。

它的核心思想是：对于一个待分类样本，计算它属于各个类别的概率，然后将其归为概率最大的那个类别。

“朴素” 体现在假设所有特征之间相互独立。虽然这个假设在现实中往往不成立，但算法在很多场景下（尤其是文本分类）依然表现良好且高效。

工作流程是：

1. 基于训练数据，统计每个类别出现的先验概率。

2. 统计在每个类别下，各个特征取值的条件概率。

3. 对新样本，利用贝叶斯公式计算其属于每个类别的后验概率

4. 选择后验概率最大的类别作为预测结果。

它优点是实现简单、训练和预测速度快、对小样本和高维数据（如文本）效果好，常用于垃圾邮件过滤、情感分析等任务。

> **贝叶斯公式** 是概率论中的一个核心定理，用于计算在已知某些证据条件下，某个假设成立的条件概率。

## 决策树的分裂指标

决策树在选择特征进行分裂时，主要依据以下几种指标来衡量分裂的好坏：

1. 信息增益（Information Gain）：

    - 基于信息熵（Entropy）的概念。

    - 信息熵衡量数据集的混乱程度，熵越大，纯度越低。

    - 信息增益 = 分裂前的熵 \- 加权平均的分裂后熵。

    - 选择信息增益最大的特征进行分裂。

    - 常用于 ID3 算法。

2. 增益率（Gain Ratio）：

    - 信息增益的一个改进，解决了信息增益偏向于选择取值较多的特征的问题。

    - 增益率 = 信息增益 / 该特征的固有值（Intrinsic Value）。

    - 选择增益率最大的特征。

    - 常用于 C4\.5 算法。

3. 基尼不纯度（Gini Impurity）：

    - 衡量从数据集中随机抽取两个样本，其类别标签不一致的概率。

    - 基尼不纯度越小，数据集纯度越高。

    - 选择能使得基尼不纯度下降最多（或分裂后加权基尼不纯度最小）的特征进行分裂。

    - 常用于 CART 算法（分类树）。

这些指标的核心目标都是通过分裂，使得子节点的“纯度”尽可能提高，从而构建出高效的分类或回归树。



## 聚类算法

聚类是一种无监督学习算法，目标是将数据集中的样本划分为若干个组（簇），使得同一簇内的样本相似度高，不同簇间的样本相似度低。

常见的聚类算法包括：

1. K\-Means：

    - 最经典的聚类算法。

    - 需要预先指定簇的数量 K。

    - 通过迭代更新质心（簇的中心点），将每个样本分配到最近的质心对应的簇。

    - 优点是简单、高效，适合球状分布的数据。

2. 层次聚类（Hierarchical Clustering）：

    - 不需要预先指定簇数量。

    - 可以构建一个树状的聚类结构（树状图）。

    - 分为凝聚式（自底向上）和分裂式（自顶向下）两种。

    - 适合分析数据的层次结构。

3. DBSCAN：

    - 基于密度的聚类算法。

    - 能发现任意形状的簇，并能识别噪声点（离群值）。

    - 通过定义“核心点”、“边界点”和“噪声点”来划分簇。

    - 适合处理有噪声且簇形状不规则的数据。

4. 高斯混合模型（GMM）：

    - 基于概率模型的聚类方法。

    - 假设数据是由多个高斯分布混合生成的。

    - 使用 EM 算法进行参数估计。

    - 能给出样本属于每个簇的“软分配”概率。

这些算法各有特点，选择时需根据数据分布、是否需要指定簇数、对噪声的敏感度等需求来决定。



## AdaBoost算法

AdaBoost（Adaptive Boosting）是一种经典的集成学习算法，属于Boosting方法。

通过组合多个弱学习器（通常是深度很浅的决策树，即决策树桩）来构建一个强学习器。

工作流程如下：

1. 初始化样本权重：开始时，所有训练样本的权重相同。

2. 迭代训练弱学习器：

    - 使用当前样本权重训练一个弱学习器。

    - 计算该弱学习器的错误率。

    - 根据错误率赋予该弱学习器一个权重：错误率越低，该学习器在最终模型中的投票权越大。

    - 更新样本权重：提高被当前弱学习器错误分类样本的权重，降低正确分类样本的权重。

3. 组合弱学习器：最终的预测结果是所有弱学习器的加权投票（分类）或加权和（回归）。

AdaBoost 的关键在于自适应地调整样本权重，让后续的弱学习器更关注之前被分错的“困难样本”，从而逐步提升整体性能。



## GBDT和XGBoost的区别

1. GBDT（Gradient Boosting Decision Tree）和 XGBoost 都是基于梯度提升的决策树算法，XGBoost 是 GBDT 的一个高效实现和重要改进。

2. 主要区别体现在以下几个方面：

    1. 损失函数优化：

        - GBDT：使用损失函数的一阶导数（梯度）来拟合残差。

        - XGBoost：对损失函数进行二阶泰勒展开，同时使用一阶和二阶导数（梯度和 Hessian）。这使得优化方向更精确，收敛更快。

    2. 正则化：

        - GBDT：通常没有内置的正则化项，容易过拟合。

        - XGBoost：在目标函数中显式加入了正则化项，控制树的复杂度（如叶子节点数、权重大小），有效防止过拟合，提升泛化能力。

    3. 分裂点选择与计算效率：

        - GBDT：通常采用贪心算法，对每个特征的所有可能切分点进行枚举，计算开销大。

        - XGBoost：支持加权分位数法（approximate algorithm）快速找到候选切分点，大幅提高大数据集上的训练速度。同时支持并行化（特征并行）和缓存优化。

    4. 缺失值处理：

        - GBDT：需要预先处理缺失值。

        - XGBoost：能自动学习缺失值的最优划分方向，在训练时确定缺失值应归于左子树还是右子树。

    



## GBDT的详细计算流程

GBDT（Gradient Boosting Decision Tree）的计算流程是一个迭代拟合残差的过程，具体步骤如下：

1. 初始化模型：用一个常数（通常是使损失函数最小的值）来初始化模型。

2. 迭代训练（m = 1 到 M）；计算负梯度（伪残差）、训练弱学习器、计算叶子节点权重、更新模型

3. 输出最终模型：经过 M 轮迭代后，最终得到预测模型

整个过程就是通过梯度下降的方式，在函数空间中逐步优化模型，每一步都用一个决策树去拟合当前的“最陡下降方向”（负梯度），从而最小化整体损失。



## GBDT适用于分类还是回归

GBDT（Gradient Boosting Decision Tree）既适用于分类，也适用于回归。

它的核心思想是通过迭代地训练回归树来拟合损失函数的负梯度（伪残差），因此基础的弱学习器是回归树。但通过选择不同的损失函数，它可以灵活地应用于不同任务：

1. 回归任务：

    - 使用平方损失（Squared Loss）或绝对值损失（Absolute Loss）等。

    - 模型直接预测连续的数值。

2. 分类任务：使用对数损失（Log Loss）

所以；GBDT 是一个通用的框架，通过调整损失函数，可以统一处理分类和回归问题。像 XGBoost、LightGBM 等实现都同时支持这两类任务。

## KNN的计算方式

KNN（K\-Nearest Neighbors）算法的计算过程分为两个阶段：预测阶段和训练阶段。

1. **训练阶段**：

- KNN 是一种“懒惰学习”（lazy learning）算法，训练阶段几乎不进行计算。

- 它只是简单地将所有训练样本的特征向量和标签存储起来。

2. **预测阶段（对新样本进行预测）**：

当有一个新样本需要预测时，执行以下步骤：

1. 计算距离：

    - 计算该新样本与每一个训练样本之间的距离。

    - 常用的距离度量包括：

        - 欧氏距离（L2）

        - 曼哈顿距离（L1）

        - 也可以使用余弦相似度等。

2. 排序并选择 K 个最近邻：

    - 将所有训练样本按照与新样本的距离从小到大排序。

    - 选取距离最近的 K 个样本（K 是一个预先设定的超参数）。

3. 聚合结果：

    - 分类任务：对这 K 个邻居的类别进行多数投票，得票最多的类别作为预测结果。

    - 回归任务：取这 K 个邻居的目标值的平均值（或加权平均）作为预测结果。

核心思想：“物以类聚”，认为一个样本的性质应该与其最接近的几个邻居相似。

KNN 的计算开销主要在预测阶段，尤其是当训练集很大时，计算所有距离会比较慢。

## 特征工程的标准化

将特征数据转换为 均值为 0、标准差为 1 的正态分布；避免某些特征因量纲大而“主导”距离计算。

KNN 依赖距离 → 距离依赖尺度 → 所以必须标准化

在鸢尾花案例中，花萼长度和花瓣宽度单位不同（cm），如果不标准化，长度可能主导分类结果

## 无监督学习

**无监督学习特点是训练数据没有标签。模型的目标是从数据本身发现隐藏的结构、模式或规律。**

主要任务类型包括：

1. 聚类（Clustering）：

    - 将数据划分为若干组（簇），使得组内样本相似，组间样本相异。

    - 常见算法：K\-Means、层次聚类、DBSCAN、GMM。

2. 降维（Dimensionality Reduction）：

    - 在保留重要信息的前提下，将高维数据映射到低维空间，用于可视化或去噪。

    - 常见算法：PCA（主成分分析）、t\-SNE、UMAP。

3. 密度估计（Density Estimation）：

    - 学习数据的概率分布，可用于异常检测。

    - 例如：高斯混合模型（GMM）。

4. 关联规则学习（Association Rule Learning）：

    - 发现数据项之间的有趣关系，如“购物篮分析”中“买啤酒的人也常买薯片”。

    - 典型算法：Apriori。
